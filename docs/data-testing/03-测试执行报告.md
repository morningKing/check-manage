## 3. 时长分层

L2 双口径（`server/pytest.ini` 注册 `slow` marker：单例**实测** >30s 才打标，fast 层 `-m "not slow"`）：

| 口径 | 命令（`cd server && PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` 前置略） | 结果 |
|------|------|------|
| 空载全量（计划⑤ T3 实测） | `python -m pytest tests/test_data_full_* -q` | 100 passed，**70.84s** |
| 空载 fast 层（T3 实测） | 同上 + `-m "not slow"` | 100 passed，**70.84s**（选集与全量相同） |
| slow 子集（T3 实测） | `-m "slow"` | 0 selected（100 deselected，6.74s） |
| 慢例候选实测（T3，两轮 `--durations=30`） | io+automation 31 例 | 总 31.38s / 22.46s，单例最慢 E09 **4.2s** |
| 收口期全量（本报告 §1 执行轮） | 九文件显式列出，同全量 | 100 passed，**37.55s** |
| 终态全量（缺陷修复收口轮，§1 终态口径） | 九文件显式列出，同全量 | **101 passed，57.15s** |

- **0 例打标的依据**：预期慢例 E08/E09/E10 的 40s 是 `_wait_etl_log` 轮询**上限兜底**而非典型耗时（调度器 2s 轮询 1–2 拍即终态）；webhook 为请求线程内同步执行（01 §4 事实#19）、无后台等待。最慢单例距 30s 阈值 7 倍余量且两轮稳定，不存在漏标——fast=full 数字相同系选集重合的必然，非漏测。
- **双读数说明**：T3 空载 70.84s 与收口期 37.55s 均为实测——T3 读数含 T2 加固前的 suite 结构差异与当时后台负载余量，37.55s 为收口期终态。
- **复标候选**：E08/E09/E10（ETL 异步轮询）、F13/F15（行动作回写）——当前实测 0.3–4.2s 未越线；若后续环境变慢（如调度器积压把轮询拖到 30s+）即按「打标以实测为准」补标，机制已就位。
- **负载期历史读数**：计划③④ 时代同套件全量曾实测 **41:58**（automation 单文件 ~8min）——并行会话/机器负载下 L2 时长可膨胀 30 倍以上。时长数字仅在空载参照系内可比；**长跑务必后台+轮询，勿前台傻等**。
- **L3 时长**：加固后 Phase C 六轮 6.5–6.9m（reload 模式 13 处 × 每轮 +1.5~2.5m）；收口期健康栈（无并行会话）两轮 **4.2m / 4.1m**；缺陷修复收口终态两轮 **5.2m / 5.2m**（含 B18 替换语义、D18b 页头直切新增步）。
