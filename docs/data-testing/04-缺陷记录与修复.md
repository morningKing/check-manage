# 缺陷记录与修复

> 记录规则（spec §9）：发现即修；每条按「现象 → 根因 → 修复 → 回归证据」登记；
> 新测试必须在修复前 commit 上失败（判别力先行）。

## #1 POST 记录缺 id → 500（TD-A23/A24，2026-10-06）

- **现象**：`POST /api/<collection>` 与 `POST /api/<collection>/batch-create` 的记录不带 `id` 时返回 500 Internal Server Error（HTML 错误页，泄漏服务端异常）。
- **根因**：`dynamic_data.id` 列 NOT NULL 且无默认值，`server/routes/dynamic.py` 的 `create_item`/`batch_create_items` 直接以 `body.get('id')`（None）入库 → psycopg2 NotNullViolation 未捕获冒泡为 500。前端恒由客户端生成 id（`addPageData` 的 `<endpoint>-<uuid8>`），故 UI 不可见，仅 API 直调触发——由数据管理 E2E 体系（计划① Task 3）发现。
- **修复**（d17bb70）：两处对缺失/空 id 服务端 `uuid.uuid4().hex` 兜底生成，单条响应回带 `id`；batch 内生成 id 天然不与唯一性预检冲突，语义仍为新增。
- **回归证据**：TD-A23/A24 在修复前 commit（23a1bf5）上运行失败（单条与批量均 500 实录）；修复后 L2 全量 **18 passed**（2026-10-06）。错误契约由「500 HTML」变为「201 + 生成 id」。

## #2 ExcelView 无条件只读，无单元格编辑回写（TD-A18b，2026-10-06）

- **现象**：Excel（Univer）视图任何单元格双击均无法进入编辑态（仅触发查看对话框/行导航）；spec 族A 设想的「Excel 单元格编辑回写」产品未实现。由计划① Task 4 的 TD-A18 探针发现，一度以 `test.fixme` 挂起。
- **根因**：`src/components/common/ExcelView.vue` 的 `setReadOnly()` 对每个 `BeforeSheetEditStart` 事件 `cancel = true`（无条件只读），且未接任何单元格值提交→数据落库的链路。
- **修复**（a71ad76）：实现标量字段（text/textarea/number/radio/select/date/datetime）单元格编辑回写——`editable` prop 权限门禁（默认 false，DynamicPage 传 `canUpdate`；非标量列保持只读并在 `BeforeSheetEditStart` 拦截）；`univerHelper` 新增 `parseCellEdit`（select/radio label→value 未匹配拒绝、number→Number NaN 拒绝）与 `cellToTarget`（复用 buildWorkbookData 布局）；`BeforeSheetEditEnd` 提交→emit `cell-edit`→DynamicPage 复用对话框更新链路（`_version` 乐观锁，409 走 `conflictMessage()`），失败经 `restoreCell` 还原单元格显示。
- **回归证据**：TD-A18b 在修复前 commit（07a62ae）上运行失败（「回写后名称应为 XLS-…-改，实为 XLS-…」实录）；修复后 L3 全量 **7 passed, 0 skipped，连续两轮稳定**，`npm run test` 前端全量 1314 例全绿，vitest ExcelView 19/19。

## #3 FileUpload.vue 移除文件路径失效，删除项复活（TD-B18，2026-10-06）

- **现象**：新增/编辑对话框内对已上传文件点移除（×）后文件从列表消失，但保存或重开编辑对话框时该文件重新出现——移除不生效；「替换某个已传文件」在真实 UI 无可用路径（先移除再重传同文件会得到两份），仅能追加。由计划② Task 4 的 TD-B18 探针发现。
- **根因**：`src/components/dynamic-form/controls/FileUpload.vue` 的 watch（:104-119）把列表项 `uid` 重映射为上传响应的下标（数字），而 `handleRemove`（:192-196）按 `f.uid !== String(file.uid)` 过滤（uid 本为 data_files 的 uuid 字符串），比较永不匹配 → 任何项都过滤不掉，被删项经 watch 重渲染复活。
- **修复**：**未修复，登记**（不阻塞族B/C 验收——TD-B18 按真实行为以「编辑追加」语义断言并在 spec 头注释声明；替换语义留待产品修复后改写用例）。
- **回归证据**：计划② Task 4 报告实录（TD-B18 编辑上传第二文件后数组为 2 个而非 1 个）+ `e2e/data-full/data-field-types.spec.ts` 头注释「已知产品缺陷：FileUpload 移除路径失效」。

## 已知限制与后续项（2026-10-06 审查裁定，均不阻塞）

1. `parseCellEdit`：纯空白文本落在 number 列会写 0（`Number(' ')===0`）——用户以空格「清空」数字单元格时静默写 0，应视为清空/拒绝（univerHelper.ts）。
2. `parseCellEdit`：选项 value 为 number/boolean 时严格等匹配不上「直接输入 value」路径（label 路径可用），boolean value 存在类型撒谎（univerHelper.ts）。
3. ExcelView 门禁只拦编辑器入口——paste 等绕过编辑器的 SetRangeValues 路径未探针，可能出现「已显示未落库」静默分歧，待探针确认后补拦或文档声明。
4. 可见字段 `filter+sort` 在 buildWorkbookData / cellToTarget / 双击处理器三处重复，布局规则变更时 cellToTarget 有静默错位风险，宜抽 `getVisibleFields` 共享。
5. select 直接输入 value 回写成功后单元格显示 value 而非 label（纯展示瑕疵，hash 机制下原地编辑几乎不重建工作簿）。
6. TD-A18b 编辑后截图被删而非改名，回写后状态无视觉证据（截图目录已 gitignore，影响仅本地留证）。
