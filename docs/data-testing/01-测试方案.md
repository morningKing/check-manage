# 数据管理功能全量测试方案

> 版本：v1.0 ｜ 日期：2026-10-06 ｜ 范围：check-manage 数据管理八大能力族（A–H）
> 设计文档：[2026-10-06-data-management-e2e-design.md](../superpowers/specs/2026-10-06-data-management-e2e-design.md)
> 配套：[02-数据管理功能测试用例.md](./02-数据管理功能测试用例.md)（03 执行报告 / 04 缺陷记录随计划⑤建立）

## 1. 背景与目标

check-manage 是配置驱动的动态数据管理平台：PageConfig 定义 schema → 动态生成 UI 与 API → 单表 JSONB 存数据。已交付的 AI 全量测试体系（`e2e/ai-full/` + `server/tests/test_ai_full_*.py` + `docs/ai-testing/` 四件套）明确将**非 AI 的数据管理功能排除在外**，且 `e2e/` 下目前没有任何针对动态数据页面的 spec——动态 CRUD、字段类型、关联、分支、导入导出、自动化引擎等系统主干处于 e2e 零覆盖状态。

本体系在数据侧**镜像 ai-full 三层结构**（文档 / L2 API / L3 E2E），沉淀一套可复用的全量回归测试资产，验证数据管理能力的功能完整性、健壮性、可靠性与安全性。

## 2. 范围

八个能力族全量覆盖（摘要自 spec §2.1）：

| 族 | 能力族 | 主要端点 / 入口 |
|----|--------|----------------|
| A | 动态数据 CRUD + 三视图 | `/api/<collection>`（无前缀动态 catch-all，RESERVED 集合排除保留路径）、`batch-*`、`row-actions/:id/run`、DynamicPage 三视图 |
| B | 字段控制类型 + workflow 状态机 | PageConfig.fields、`/workflow/*` |
| C | 关联体系 | `/relations/*`、`/relation-graph/*`（`data_relations` 表） |
| D | 项目分支 + 跨项目依赖 | `/project-versions/*`、`/projects/*/dependencies*` |
| E | 数据进出（导入/导出/ETL） | `/importRuns*`、`/exportScripts*`、`/etlTasks*` 等 |
| F | 自动化引擎 | `/triggerRules*`、`/validationScripts*`、`/webhook/*`、行动作 |
| G | 列视图 + 查询台 | `/<page_id>/views*`、`/query/*` |
| H | 周边支撑 | `/comments/*`、`/timeline/*`、备份端点 |

明确排除（摘要自 spec §2.2）：

- AI 侧能力（已被 ai-full 覆盖），仅在与 AI 交互相交处不重复展开；
- 工厂重置 FactoryReset——破坏性操作，不进自动化用例；
- L1 单测查漏补缺——缺口另行立项；
- 智能客服 kefu、首页组件、工作流设计器画布等非数据管理模块。

## 3. 分层与交付物

三层全家桶（摘要自 spec §3）：

| 层 | 位置 | 形态 |
|----|------|------|
| 文档 | `docs/data-testing/` | 四件套：01 方案 / 02 用例 / 03 执行报告 / 04 缺陷记录与修复，格式对齐 `docs/ai-testing/`（03/04 随计划⑤建立） |
| L2 API | `server/tests/test_data_full_<族>.py`（八族各一） | pytest，健壮性/边界/越权/状态机断言 |
| L3 E2E | `e2e/data-full/helpers.ts` + 八族各一 spec | Playwright 真实前后端链路（非 mock）；helpers 承载 DTEST- 前缀脚手架与二段删清理 |

关键约定（摘要自 spec §4）：

1. 测试资产一律 `DTEST-<族>-<用途>-<时间戳>` 前缀，与 AI 套件 `AITEST-` 互不干扰；
2. 用例自建页面：每条用例（或每 spec 的 beforeAll）自建 PageConfig + Menu，collection 天然隔离，不依赖共享 demo 数据；
3. 登录走真实 `/api/auth/login`（admin/admin123）+ 共享 `e2e/.auth/admin.json`；低权限角色用例临时建角色/用户，用后删除；
4. L3 模式：API 断言为主 + 关键节点截图留证；但三视图操作与表单控件用例必须真实浏览器交互，不得用 API 绕过；
5. Webhook stub 在测试进程内起本地 HTTP server，不依赖外部服务；
6. 环境依赖顺序：Postgres → Flask(:3002) → Vite(:5173)；本套件不依赖 OpenCode/MCP（与 ai-full 的关键差异）。

补充（本套件实测口径）：**L2 打真实 dev 栈——默认经 Vite :5173 代理访问 /api（转发至 Flask :3002），服务不在时 skip 而非 fail**；**L3 沿用根 `playwright.config.ts`，workers=1** 串行执行。

## 4. 已核实的环境事实（2026-10-06，#1–#7 族A 打样期间验证，#8–#11 计划② 族B/C 落地期验证）

1. `POST /pageConfigs` 不落 viewConfig（INSERT 列清单未含），需 `PUT /pageConfigs/<id>` 补写；
   看板配置存 `viewConfig.kanban`。
2. `DELETE /menus/<id>` 只删 menus 行，不级联 page_configs / dynamic_data ——
   清理必须二段删（记录 → pageConfig → menu），helpers.deleteDataPage 已固化（TD-A20）。
3. 动态数据端点为无前缀 catch-all `/api/<collection>`，RESERVED 集合排除保留路径；
   主键重复 409；过期 `_version` PUT 409 VERSION_CONFLICT；
   未知 collection GET 返回 200 空集（404 仅用于 RESERVED 保留名）。
4. 列表查询参数：page/pageSize/all/keyword/q（mongo）/ids/locateId/sort/order。
5. 数据页名称全局唯一（menus 部分唯一索引），测试名必须带时间戳。
6. L2 经 Vite 代理访问 /api——Flask :3002 不挂 /api 前缀；
   `DATA_FULL_BASE_URL` 默认 `http://localhost:5173`。
7. 记录 id 惯由客户端生成；2026-10-06 起服务端对缺 id 的 create/batch-create
   以 uuid 兜底（修复记录见 04 #1），Excel 视图支持标量字段单元格编辑回写
   （`editable` 权限门禁，修复记录见 04 #2）。
8. **autoTimestamp / compositeText 纯前端**：服务端零处理——store 在
   add/updatePageData 落库时填充/计算；API 直连 create/update 既不填充 ts
   也不重算 composite（TD-B07/B08 断言「服务端没存」，API 直改源字段 composite 残留旧值）。
9. **workflow 两套并存**：字段级 `workflowConfig` 经记录 PUT 流转（非法转换/角色不符
   → 400，`roles: []` 所有角色可转，首次写入 old=None 完全绕过校验）；跨页编排走
   `workflow/definitions|instances|inbox`（实例响应 snake_case `workflow_id` 等；
   `assignedRoles` 不符 → 403 且整个事务回滚，状态字段不变；空数组=所有人可见）。
   两套共存时字段级先校验——状态字段挂空 `transitions` 的 workflowConfig 会以 400
   拦下编排推进（TD-B10–B14）。
10. **reference 父删除 RESTRICT**：单条 DELETE 409「无法删除：被「…」引用」；
    batch-delete 的实际契约是 HTTP 200 + `deleted:0` + `blocked` 映射（非 409）；
    继承仅显示层——服务端不拷贝父字段，前端以 `_ref_` 键解析显示（TD-C06/C07）。
11. **relation / quoteSelect / 文件**：`PUT /relations/<c>/<r>/<f>` 全量替换 + 双向同步，
    对不存在的记录 PUT 不 404；quoteSelect 值为记录 JSON 内 id 数组，被引记录删除后
    悬挂 id 不清理（前端回退显示原始 id）；文件上传扩展名白名单按字段级
    `fileConfig.allowedExtensions` 校验，越界 400（TD-C10/C08/B09）。

## 5. 维度与准出 / 数据隔离 / 缺陷流程 / 实施节奏

### 5.1 测试维度与准出（摘 spec §6）

| 维度 | 数据侧关注点 | 准出标准 |
|------|-------------|----------|
| 功能完整性 | 每个端点/UI 入口正路径、分支状态机、ETL/导入状态流转、边界值（分页、批量上限、文件大小） | 高/中优先级用例全部通过 |
| 健壮性 | 畸形 JSON、不存在资源 404 不泄漏存在性、错误契约（中文 error + code）、并发建单/并发更新 | 无 500 泄漏堆栈 |
| 可靠性 | ETL 中断后重跑幂等、导入失败行重试、分支合并冲突收敛、锁防串写 | 容灾机制按设计生效 |
| 安全性 | 跨 collection/记录 IDOR、低权限角色写被拒、校验/导出脚本执行面约束 | 安全用例 100% 通过，发现即修 |

### 5.2 数据隔离与清理（摘 spec §7）

- 清理顺序：先删分支/依赖/关联/记录 → 再删 menu 与 pageConfig。menu 删除不级联（见 §4 第 2 条），helpers 提供二段删。
- 每条用例 afterAll/teardown 自清理；异常中断残留靠 `DTEST-` 前缀做 dev 库定点清理。
- 红线：不修改/删除任何非 `DTEST-` 数据；不触发工厂重置；备份用例产物测完即删；低权限角色/角色授权用后删除。

### 5.3 留证与执行（摘 spec §8）

- 截图：`e2e/screenshots/data-full/`（Playwright 自动留证 + 关键节点显式截图）；
- 关键证据归档 `docs/data-testing/evidence/`（导出文件、webhook payload、合并 diff、冲突解决过程）；
- 每轮全量执行 = `npx playwright test e2e/data-full` + `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest server/tests/ -k test_data_full -v`，结果写入 03-执行报告；
- 规模预估：L2 约 80–120 例、L3 约 40–60 例，以 02-用例文档定稿为准。

### 5.4 缺陷流程（摘 spec §9，硬规则）

1. **发现即修**：缺陷立即修复，逐条记入 `04-缺陷记录与修复.md`（现象 → 根因 → 修复 → 回归证据）。
2. **判别力先行（硬规则）**：新测试必须先在修复前的 commit 上跑出失败，证明测试能抓住问题，再修复转绿。
3. 行为变更涉及用户可见语义的，同步核对 `docs/user-guide/` 对应文档。

### 5.5 实施节奏（摘 spec §10）

- 分支：`feat/data-e2e`；
- 顺序：helpers + 族A 打样（已含环境事实核实，见 §4）→ 族B/C → 族D/E → 族F/G/H → 02-用例文档定稿 → 首轮全量跑 → 03-执行报告 + 04-缺陷记录；
- 每族独立跑绿后再进下一族；中途发现缺陷按 §5.4 处置。
