AI Open API Reference

把 AI 能力开放给外部系统

除了数据集合读写接口，check-manage 还把六类 AI 相关能力经同一套 API Key 体系开放出来：单会话问答、批量文件处理、行级 AI/Webhook 触发、定时扫描任务、Prompt 模板管理、长期记忆管理。全部收发 application/json（文件上传除外）。

Base URLhttp://<host>:<port>/api/v1
生产入口http://localhost:8080/api/v1
认证头X-API-Key: cm_xxx
error 语言中文

与数据集合接口的关系：`/api/v1` 这个 Base Path 下同时挂了两类接口——数据集合读写接口按「页面是否开放 API 访问」授权，本页描述的六类 AI 接口按「密钥是否绑定用户」授权，两者共用同一套 API Key，但权限维度不同，见下一节。

六类能力共用的两个约定：① 所有接口要求密钥已绑定创建者（下方「认证与密钥绑定」）；② error 字段一律是中文——这是 AI 相关端点家族的既有惯例，与数据集合接口的英文 error 文案不同。

Authentication

认证与密钥绑定

六类 AI 接口都在数据集合接口的 X-API-Key 鉴权基础上，多加了一条「密钥必须绑定用户」的前置要求。

headers
X-API-Key: cm_A1b2C3d4E5f6G7h8I9j0K1l2M3n4O5p6Q7r8S9t0U1v2

为什么要绑定用户

AI 相关操作会以某个用户的身份运行 AI 会话、占用其额度、把任务/记忆/模板关联到该用户，因此密钥必须绑定创建者（owner_user_id）才能调用这六类接口——单纯的数据读写接口没有这条限制。

本功能上线前创建的存量密钥没有绑定关系，拿它们调用任何一个本页描述的接口都会返回：

403
{ "error": "该密钥未绑定用户，请在密钥管理中重新创建" }

解决办法：去密钥管理页重新创建一个新密钥（新建的密钥会自动绑定当前登录用户），旧密钥无法通过编辑补上绑定关系。新建路径：管理员登录系统 → 「系统配置 → 集成对接 → Open API」→「创建密钥」。新建的密钥同时可用于本页六类接口和数据集合接口。

隔离粒度：按密钥，不是按账号

每把 API Key 只能看到、操作它自己创建的批任务/单会话/模板；用同一账号新建的另一把密钥调用同样接口，看到的列表不会包含对方创建的资源，查/删/改对方的资源一律 404（不用 403，不泄漏存在性）。暂存文件（批任务上传）例外：按用户隔离而非按密钥，同一用户名下的多把密钥共享同一个暂存空间。行操作触发、AI 定时任务同样按创建者/所属用户过滤。

AI 单会话 · 1

创建单会话

给一句 prompt（可选带上几个文件），创建一个独立 AI 会话；跟批任务共用同一套执行引擎（并发/超时/失败检测），区别是没有子任务概念——随附的文件全部进同一个 AI 会话，不像批任务那样按文件拆分。

POST /api/v1/ai-sessions 需绑定密钥
request body
{
  "prompt": "帮我用三句话总结一下敏捷开发的核心理念。",
  "agent": "",
  "model": "",
  "title": "",
  "files": []
}
字段必填说明
prompt是下发给 AI 会话的指令，最长 20000 字符
agent否指定 OpenCode agent；留空用系统默认，可选值见 批任务 agents 端点
model否指定模型（<providerID>/<modelID>）；留空用默认，可选值见 批任务 models 端点
title否会话标题；不传默认「新会话」
files否要让 AI 读取的文件，形状同批任务的 files：[{name,path}]；path 来自 批任务上传接口（单会话没有自己专属的上传端点，复用同一个）。留空 = 纯文本会话；单次最多 50 个，不要求来自同一次上传调用

先传文件，再建会话：POST /api/v1/ai-batches/uploads 拿到 {name,path}，原样放进本接口的 files 数组即可——跟批任务共用同一个暂存池，只是消费方不同。

response · 201
{ "sessionId": "b1c2d3e4-...", "status": "pending" }
状态码触发条件
400prompt 缺失/为空；超过 20000 字符；files 不是数组/超过 50 个/缺字段；files[].path 不合法或指向的文件已过期/不存在
401/403密钥缺失/无效/已停用/未绑定用户

AI 单会话 · 2

查询会话状态

GET /api/v1/ai-sessions/{sessionId}
response · 200
{
  "sessionId": "b1c2d3e4-...",
  "status": "completed",
  "title": "新会话",
  "agent": null,
  "model": null,
  "createdAt": "2026-08-18T03:20:00.000Z",
  "lastActiveAt": "2026-08-18T03:20:12.000Z",
  "output": "敏捷开发的核心理念可以概括为三点：……",
  "error": null,
  "files": [],
  "usage": { "durationMs": 8340, "tokensInput": 1200, "tokensOutput": 210, "cost": 0.0041 }
}
字段说明
statuspending / running / completed / failed / cancelled
output只在 status='completed' 时非 null——运行中/失败可能已落库半截文本，不设这道门会把截断输出当结果返回
error只在 status='failed'/cancelled 时非 null，可读的失败原因（cancelled 时是固定的"已被调用方取消"说明）
files创建时随附的文件，[{"name": "report1.pdf"}]；没有文件时为 []，只回显文件名
usage用量汇总（durationMs/tokensInput/tokensOutput/cost），还没有可用数据时为 null；仅供成本核算参考
状态码触发条件
404sessionId 不存在，或不是用这把密钥创建的（不区分，均 404）

建议轮询间隔 3~10 秒，无 SSE 推送。没有 list/delete/continue/retry，也没有批任务那套 /files//files/download 事后查看产出文件的能力——只有创建、查状态、取消三个端点，附带的文件只是这一轮的输入；需要更完整的生命周期管理或产出文件管理，请用下方「AI 批任务」（可以只传一个文件）。

AI 单会话 · 3

取消会话

POST /api/v1/ai-sessions/{sessionId}/cancel 需绑定密钥

协作式取消，不是立即生效：pending 会话在下一轮调度时直接标记 cancelled；running 会话在下一次轮询时（通常几秒内）被中止后标记 cancelled——调用后仍需轮询「查询会话状态」确认。

response · 200（字段同「查询会话状态」）
{
  "sessionId": "b1c2d3e4-...", "status": "cancelled",
  "output": null, "error": "已被调用方取消", "usage": null
}
状态码触发条件
404sessionId 不存在或不属于本密钥
409会话已处于终态（completed/failed/cancelled）

AI 批任务 · 生命周期 5.1

上传文件

POST /api/v1/ai-batches/uploads 需绑定密钥

multipart/form-data，字段名固定为 files，可重复出现以一次上传多个。

response · 201
{
  "files": [
    { "name": "report1.pdf", "path": "batch-staging/u-123/a1b2c3d4/report1.pdf" }
  ]
}

path 是不透明字符串，创建批任务时原样传回，不要自行拼接或修改。

限制：单文件最大 20 MB；单次请求累计最大 100 MB；整个请求体超过 101 MB 直接 413（不解析请求体）。

暂存 24 小时后清理（按目录最后修改时间，不看是否已被引用）——拿到 path 后请尽快创建批任务，不要隔天再用；清理由下一次 /uploads 顺带触发，按用户维度扫描整个暂存目录（会波及界面手工上传的暂存文件）。

AI 批任务 · 生命周期 5.2

创建批任务

POST /api/v1/ai-batches 需绑定密钥

每个文件对应一个隔离的 AI 子会话，并发处理（限流 3 个并发）。

request body
{
  "name": "季度报告分析",
  "prompt": "请总结每份文档的核心结论，并列出风险点。",
  "files": [ { "name": "report1.pdf", "path": "batch-staging/u-123/a1b2c3d4/report1.pdf" } ],
  "agent": "",
  "model": "",
  "callbackUrl": "",
  "callbackSecret": ""
}
字段必填说明
name是批任务名称
prompt是下发给每个文件对应会话的指令，最长 20000 字符
files是/uploads 返回的 files 数组（或子集），最多 50 个
agent / model否同单会话
callbackUrl否批任务进入终态时接收 HMAC 签名回调的 URL（见 完成回调）；留空只能轮询
callbackSecret否计算回调签名用的密钥
response · 201
{ "batchId": "b1c2d3e4-...", "status": "pending", "total": 2 }
状态码触发条件
400name/prompt 缺失；prompt 超长；files 为空/超过 50 个/缺字段；files[].path 不合法或指向的文件已过期/不存在；callbackUrl 格式不对
413请求体超过 1 MB（JSON 接口）

AI 批任务 · 生命周期 5.3

修改批任务配置

PATCH /api/v1/ai-batches/{batchId} 需绑定密钥

请求体字段与创建相同（agent/model/callbackUrl/callbackSecret，均可选）。响应字段同「查询批任务详情」。

整体替换，不是局部 patch：省略的字段会被清空为默认值——只传 agent 而不重传已配置好的 callbackUrl，会把回调配置一并清空。每次调用都要把想保留的字段一起带上。修改在下一次 worker 拾取该批任务时生效（retry-failed/reexecute/continue/待执行子任务），不影响正在跑或已完成的子任务。

状态码触发条件
400callbackUrl 格式不对
404batchId 不存在或不属于本密钥

AI 批任务 · 生命周期 5.4

完成回调（Webhook）

POST <callbackUrl>

创建/修改批任务时设置了 callbackUrl，批任务进入终态（completed/partial/failed）时收到一次 HTTP POST，不必再轮询。

request
Content-Type: application/json
X-Webhook-Timestamp: 1755400000
X-Webhook-Signature: <hex>
X-Webhook-Event: ai_batch_completed

{
  "event": "ai_batch_completed", "batchId": "b1c2d3e4-...",
  "status": "completed", "total": 2, "done": 2, "failed": 0
}

签名校验：X-Webhook-Signature = HMAC-SHA256(secret, "{timestamp}.{原始请求体}")。超时/重试：30 秒超时，失败重试 3 次（间隔 1 秒），全部失败不影响批任务状态本身。

可能不止一次：retry-failed/append/continue 都能把已终态的批任务重新拉回运行中，之后再次收敛到终态会再触发一次回调——按 status 处理，不要假设只调用一次。

AI 批任务 · 生命周期 5.7

取回处理结果

GET /api/v1/ai-batches/{batchId}/results
response · 200
{
  "batchId": "b1c2d3e4-...", "status": "completed",
  "results": [
    { "name": "report1.pdf",  "status": "completed", "output": "……AI 的完整回复文本……", "error": null, "usage": { "durationMs": 22110, "tokensInput": 6400, "tokensOutput": 320, "cost": 0.0156 } },
    { "name": "report2.docx", "status": "failed",    "output": null, "error": "OpenCode 会话超时", "usage": null }
  ]
}

results[].name 取自 files[].path 的最后一段（安全化后的文件名），不是创建时传入的 files[].name。output 只在该子任务 status='completed' 时非 null；未到终态也能调用，只是部分/全部 output 仍是 null。status 还可能是 cancelled（见「取消批任务」），此时 error 为固定说明文案。usage 是该子任务自己的用量，还没有可用数据时为 null。results 数组按创建时 files 的顺序返回。

AI 批任务 · 生命周期 5.8

删除批任务

DELETE /api/v1/ai-batches/{batchId} 需绑定密钥
response · 200
{ "deleted": true }

不可逆：清理该批任务下每个子任务的 AI 会话工作区，并删除数据库记录（含全部处理结果）。删除前如需保留结果，先调用「取回处理结果」。

AI 批任务 · 生命周期 5.8a

取消批任务

POST /api/v1/ai-batches/{batchId}/cancel 需绑定密钥

请求取消该批任务下所有还没结束的子任务（pending/running）。协作式取消：排队中的直接标记 cancelled（不占并发槽位、不消耗 AI 调用）；正在执行的会在下一次轮询时（通常几秒内）被中止后标记 cancelled——调用后仍需轮询「查询批任务详情」/「取回处理结果」确认。被取消的子任务计入批任务的 failed 计数，但自身 status 忠实记录为 cancelled。已取消的子任务可用「在子会话上继续对话」或「重新执行单个子会话」重新拉起。

response · 200（字段同「查询批任务详情」）
{ "batchId": "b1c2d3e4-...", "status": "running", "total": 2, "done": 0, "failed": 1 }
状态码触发条件
404batchId 不存在或不属于本密钥
409批任务已处于终态（completed/partial/failed），没有可取消的子任务

AI 批任务 · 生命周期 5.9

重试失败子任务

POST /api/v1/ai-batches/{batchId}/retry-failed 需绑定密钥

把 failed 的子任务重置为 pending，保留原有 prompt/agent/model 配置，交由后台重新处理。

response · 200
{ "retried": 1 }

没有失败子任务时返回 {"retried": 0}，不算错误。只有批任务处于终态（completed/partial/failed）才允许调用。

状态码触发条件
404batchId 不存在或不属于本密钥
409批任务处于 pending/running（非终态）

AI 批任务 · 生命周期 5.10

追加文件

POST /api/v1/ai-batches/{batchId}/append 需绑定密钥

给已存在的批任务再加几个文件，沿用原有 prompt/agent/model。不要求终态——任何状态都可追加，这点与「重试失败」不同。

request body
{ "files": [ { "name": "report-03.pdf", "path": "batch-staging/.../report-03.pdf" } ] }
response · 200
{ "batchId": "b-1", "status": "running", "total": 6, "appended": 1 }

会让批任务退出终态：新子任务以 pending 入队，批任务状态从终态回到 running；已完成的子任务不受影响、不会重跑。如果把「进入终态」当作整批完成的信号，追加之后需要重新开始轮询。不能换 prompt——追加沿用原有配置，需要换 prompt 请新建批任务。

AI 批任务 · 子会话 5.11

获取子会话文件记录

GET /api/v1/ai-batches/{batchId}/file-records

获取每个子会话工作区中被自动记录的新增/修改文件；即使文件后来被还原或删除，记录仍保留（不是实时扫描，实时扫描见下方「子会话文件列表」）。

response · 200
{
  "batchId": "b1c2d3e4-...", "status": "completed",
  "results": [
    { "name": "report1.pdf", "seq": 1, "status": "completed",
      "files": [ { "path": "output/analysis.md", "status": "added", "dataFileId": null } ] }
  ]
}

files[].status：added / modified；dataFileId 非空表示该文件已导入系统 data_files。

AI 批任务 · 子会话 5.12

导入子会话文件到系统

POST /api/v1/ai-batches/{batchId}/import 需绑定密钥

把子会话工作区里被自动记录过的文件导入系统 data_files，返回文件 ID。白名单机制：只有被记录过的路径才能导入，防止借此端点搬运工作区里任意文件。

request body
{ "name": "report1.pdf", "paths": ["output/analysis.md", "data/results.csv"] }
字段必填说明
name / seq二选一定位子会话（文件名或序号）
paths是要导入的工作区相对路径，单次最多 100 个
response · 200
{
  "results": [
    { "path": "output/analysis.md", "status": "imported",
      "file": { "id": "df-abc123", "name": "analysis.md", "size": 1234, "mimeType": "text/markdown", "url": "/api/data-files/df-abc123/download" } }
  ]
}

幂等：已导入过的文件再次导入返回 existing 状态和原文件 ID。错误码：NOT_RECORDED / BAD_PATH / FILE_MISSING / TOO_LARGE / IMPORT_FAILED。

AI 批任务 · 子会话 5.13

获取子会话对话历史

GET /api/v1/ai-batches/{batchId}/sessions/{childId}/messages

childId 怎么填：先调「取回处理结果」，响应里每条的 name（文件名）或 seq（序号）都可以作为 childId——report1.pdf 和 1 定位同一个子会话，纯数字按序号匹配，否则按文件名匹配。本节及以下 5 个端点通用此规则。

response · 200
{
  "child": { "name": "report1.pdf", "seq": 1, "status": "completed" },
  "messages": [
    { "id": "msg-001", "role": "user", "content": [{ "type": "text", "text": "请总结这份报告..." }], "createdAt": "..." },
    { "id": "msg-002", "role": "assistant", "content": [
        { "type": "text", "text": "报告核心结论如下..." },
        { "type": "tool_use", "id": "tu-1", "name": "read", "input": { "path": "uploads/report1.pdf" } }
      ], "createdAt": "..." }

Row Actions

触发行操作

POST /api/v1/collections/{collection}/{recordId}/row-actions/{actionId}/run 需绑定密钥

用 API Key 直接触发数据页上已配置好的行操作按钮（Webhook 或 AI 扫描任务），效果和登录用户在「⋯」菜单里点这个按钮完全一样——同一条 run_action 编排、同一套幂等闸门、同一套状态回写。

request body
{ "params": { "note": "外部系统触发" } }

可见角色按密钥绑定用户本人的角色判断。写入权限：目标集合必须开启「允许写入」。actionId 不提供发现端点，需线下从配置该行操作的管理员处获取。params 原样透传，不做二次校验。默认作用于系统配置的对外默认分支，可用 ?branchId= 指定。

response · 200
{ "ok": true, "status": "running", "statusField": "status", "runningValue": "处理中" }

status 为 submitted（无状态门/webhook 已发出）或 running（有状态门，正在轮询终态）；statusField/runningValue 仅 status='running' 时非空。

状态码触发条件
400该动作已停用
403集合未开放写入；调用方角色不在可见角色白名单
404集合不存在/未开放；记录不存在；actionId 不存在；密钥未绑定用户
409该行有正在执行的动作（幂等闸门）；AI 动作绑定的扫描任务作用于另一个分支

Error handling

错误处理

统一错误格式

error shape
{ "error": "错误描述信息", "code": "INVALID_ARGUMENT" }

本页描述的六类接口 error 文案一律是中文，与数据集合接口的英文 error 约定不同（唯一例外：数据集合接口自身在文件类型校验失败时也会返回中文提示）。

code 是新增的机器可判别字段，error 字符串本身的形状/语言不受影响——程序化判断请优先用 code。未预期的服务端异常也保证返回这个 JSON 形状（而不是 HTML 错误页），code 为 INTERNAL_ERROR。

通用错误码

状态码code触发条件
401—请求头缺少 X-API-Key / 密钥不存在 / 密钥已停用（更底层的鉴权网关统一处理，不带 code）
403FORBIDDEN密钥未绑定用户（存量密钥），见「认证与密钥绑定」
400INVALID_ARGUMENT请求参数校验失败（缺字段/超长/格式不对等）
404NOT_FOUND目标资源不存在，或存在但不属于本密钥（不区分两种情况，不泄漏存在性）
409CONFLICT对处于非终态的资源调用只允许终态操作的端点（retry-failed/continue/reexecute），或对已终态资源调用 cancel

FAQ

常见问题

用旧密钥调用一直返回 403，什么原因？
本功能上线前创建的密钥没有绑定用户，去密钥管理页新建一个密钥即可，详见「认证与密钥绑定」。
批任务和单会话该选哪个？
要一个综合答案（哪怕带几份文档，也是放一起分析），用单会话；需要把 N 个文件各自独立处理成 N 份结果、需要追加/继续对话/重试/删除等完整生命周期管理，用批任务（批任务也支持只传一个文件）。单会话的文件支持是"全部塞进同一个 AI 会话"，不按文件拆分子任务。
批任务一直卡在 running 不结束怎么办？
先确认没有子任务卡在 pending（说明后台 worker 尚未处理到）；长时间无进展可联系管理员核实 AI 会话是否异常。批任务本身没有暴露给外部 API 的超时自动失败机制。
除了轮询，有没有办法在批任务完成时主动收到通知？
有。创建批任务或事后 PATCH 时设置 callbackUrl，批任务进入终态时会收到一次 HMAC 签名的 HTTP 回调，见「完成回调（Webhook）」。回调是尽力而为，建议同时保留轮询作为兜底。
continue 和 retry-failed 有什么区别？
retry-failed 只能重试失败的子任务，新建一个 AI 会话并用原始 prompt 重跑，历史不保留。continue 可以对已完成或失败的子会话追加新 prompt，复用原有 AI 会话，历史完整保留。简单说：retry-failed 是「重来」，continue 是「接着做」。
通过 API 创建的批任务，登录界面的账号本人能不能看到、能不能删？
能看到，也能删——而且能重试、能改 agent/model、能追加文件、能重新执行单条子任务，权限和界面手工创建的批任务完全一样。批任务的密钥隔离只挡「别的密钥/别的账号」，挡不住密钥所绑定账号本人在界面上的操作。
行操作的 actionId、扫描任务的 taskId 怎么获取？
这两套接口都不提供发现/列表端点（AI 定时任务的列表端点除外），需要线下从配置它们的管理员那里获取，和批任务需要先知道 batchId 是同一类约定——本页只覆盖"已知 id 之后如何调用"。
AI 类型的行操作，状态字段该怎么配？
不需要配。AI 类型行操作的执行状态与结果回写，一律使用所绑「AI 扫描任务」自己的状态字段配置——终态回写由扫描任务的引擎完成，行操作层面不重复设置，详见 row-actions.md。
记忆的 memory_id 能自己编吗？
不能。memory_id 是 mem0 生成的不透明 UUID，删除时服务端会先校验这条记忆确实属于当前密钥所属的用户，猜测/枚举他人的 id 一律返回 404。
API Key 泄露了怎么办？
立即登录系统，在「Open API」管理页面停用该密钥，然后创建一个新密钥重新分发给外部系统——记得新密钥同样需要走一遍「已绑定用户」的新建流程。
