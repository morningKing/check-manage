# AI 技能与 SkillOpt 拟合优化

> **路径**：设置中心 → AI 能力 → **AI 技能**（「技能广场」/「拟合优化」两个页签）
> **权限**：「AI 技能」入口对持有 `admin.ai_settings` 或 `admin.ai_chat_admin` 的用户可见；「技能广场」页签需 `admin.ai_settings`，「拟合优化」页签需 `admin.ai_chat_admin`
> **相关设计**：机制细节见设计文档 `docs/design/ai/08-Skill与SkillOpt.md`

---

## 这是什么

平台里的「技能（Skill）」是一段随会话提供给 AI 的指令包（SKILL.md + 辅助文件），让 AI 在特定任务上按既定套路执行。技能存在三个层次：

| 层次 | 存放位置 | 谁维护 | 生效方式 |
|---|---|---|---|
| **平台技能库** | 平台中心存储（本页「技能广场」管理） | 管理员 zip 上传 | 启用的技能**自动注入每个新会话**，即传即用 |
| **运行时技能** | OpenCode 全局配置目录 | 运行时页签直接编辑 / 从平台库发布 | **重启 OpenCode 后生效**（无热加载） |
| **会话技能** | 单个会话的工作区内 | 用户在会话中上传 | 只对该会话可用（见 [AI 助手](./assistant.md)） |

「拟合优化（SkillOpt）」在其上提供治理能力：按技能定义里声明的**步骤契约**与实际执行轨迹比对，得出每个任务的拟合度，并用 AI 辅助生成/修正步骤契约。

## 入口

进入 **设置中心 → AI 能力 → AI 技能**，页面有两个页签：

- **技能广场**：平台技能库的管理（上传、启停、删除、文件预览）；
- **拟合优化**：任务拟合与调用聚合的治理视图。

## 技能广场：管理平台技能库

### 上传技能（zip）

1. 在「技能广场」页签点 **上传技能**，选择技能 zip 包；
2. 填写描述（可留空，留空时从包内 SKILL.md 的描述提取）；
3. 提交后技能出现在列表中，默认**启用**。

zip 包需满足的契约：

- 根目录有 `SKILL.md`，或**单层目录且其下有 SKILL.md**（上传时自动剥离目录前缀）；
- 大小 ≤ 5 MiB、条目 ≤ 200 个；
- 技能名来自 SKILL.md 的 frontmatter `name`（缺失时回退 zip 文件名），只能用字母/数字/`-`/`_`，≤64 字符；
- 同名技能已存在会报错（先删除旧技能，或重命名后再传）。

### 启用 / 停用 / 删除

- 列表中每行有**启停开关**：停用后不再注入新会话（已在运行的会话不受影响）；
- **编辑**可修改描述；**删除**会同时清除平台存储与元数据；
- 平台自带**内置技能**（随部署自动种入），同样可在此启停。

### 技能怎么到达会话

启用的平台技能会**自动注入**到之后创建的每个新会话（含批任务子会话）——无需手工挂载，会话中即可使用。这是与「运行时技能」最大的区别：平台技能**即传即用**，运行时技能须重启 OpenCode。

## 发布到运行时

若希望技能以**运行时技能**的方式存在（OpenCode 全局目录、对所有会话恒定可见），可从平台技能库「发布」：

1. 进入 **设置中心 → AI 能力 → AI 配置（「运行时」页签）**，见 [OpenCode 运行时管理](./runtime.md)；
2. 在「技能 (Skill)」页签点 **从平台技能库发布**，选择要发布的平台技能；
3. 发布是**复制**：之后平台库里的同名技能再怎么改，运行时副本不会跟着变；
4. 发布成功后需**重启 OpenCode** 才生效。

## 拟合优化：任务拟合

「任务拟合」回答：**AI 实际执行是否按技能定义声明的步骤走**。前提是技能（或 Agent）定义的 frontmatter 里声明了步骤契约（`fit.steps`：每步一个 id、中文名与期望的工具调用）。没有声明步骤契约的定义不参与拟合。

页面为左右主从布局：左栏是定义清单（含拟合率），右栏有三个子页签：

- **概览**：选中定义的拟合指标汇总；
- **结果**：按任务的拟合结果列表——得分、状态（fit 完全吻合 / partial 部分吻合 / diverged 偏离 / reordered 做了但次序不对 / no_trace 无轨迹 / parse_error 定义解析失败），展开可看逐步骤的命中证据（工具 + 参数摘要 + 时间）；
- **版本**：定义内容每次变更生成一个版本，时间线上对比各版本的拟合率变化；可给版本加人读的标注（如「v2 增加校验步骤」）。

对拟合度不理想的任务，可以：

- **重算**：对指定任务重新计算拟合（幂等）；
- **AI 诊断**：对「部分吻合/偏离」的结果发起诊断，产出偏离原因与修正建议；
- **AI 步骤生成 / 回写**：让 AI 读定义全文生成步骤契约草案，可先**试算**（拿历史任务验证命中率，不落库），确认后**回写**到定义文件——回写前会校验正则合法性，非法正则不会写盘。

红线：生成、诊断、试算都**只产出建议与预览**，真正修改定义文件的只有人工点击「回写/保存」这一步。拟合结果只进治理视图，**不会**因拟合度低而阻断或重试任务。

## 拟合优化：调用聚合

「调用聚合」页签回答：**每个技能被调用了多少次、效果如何**。

- 调用计数**两列分开**：`runtime`（运行时确证——插件实际观测到技能加载/调用）与 `heuristic`（启发推断——从执行清单推定），界面永不把推断呈现为确证；
- **版本 Δ**：同一技能不同内容版本之间的完成率对比，看「这次改动是变好还是变坏」；
- **建议效果追踪**：对 AI 优化建议标记「接受/拒绝/应用」后，这里可查看应用建议前后 7 天的指标对比。相关建议反馈的采集机制见 [AI 执行审计](./execution-audit.md)。

## 常见问题

**上传的技能在会话里用不了？**
依次检查：技能是否**启用**；SKILL.md 的 frontmatter `name` 与 `description` 是否齐全（描述缺失会被运行时静默过滤）；会话是否是**上传之后新建**的（注入只发生在新会话）。若想覆盖所有会话且不依赖注入，走「发布到运行时 + 重启」。

**「从平台技能库发布」之后改了平台技能，运行时为什么不更新？**
发布是复制不是引用——两侧内容各自演化。需要同步时重新发布一次，再重启 OpenCode。

**拟合结果里没有某个技能？**
该技能的定义没有声明步骤契约（`fit.steps`），或定义文件已被清理且无历史缓存——两者都不产生结果行（不是 0 分）。

**拟合分低会影响任务执行吗？**
不会。拟合结果只是治理证据，不参与任何执行侧判定；门禁（见 [AI 动作门禁与执行前审批](./action-gate.md)）才是执行侧的强约束。

**技能广场页面下方还有一张「MCP 服务」卡片？**
那是 MCP 服务管理入口，见 [MCP 服务管理](./mcp-servers.md)。
