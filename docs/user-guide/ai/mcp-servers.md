# MCP 服务管理（内置与外部）

> **路径**：设置中心 → AI 能力 → **AI 技能（「技能广场」页签）**，页面下方的「MCP 服务」卡片
> **权限**：`admin.ai_settings`
> **相关设计**：机制细节见设计文档 `docs/design/ai/10-管理配置与外部MCP.md`

---

## 这是什么

AI 会话通过 **MCP（Model Context Protocol）** 获得工具能力。平台管理两类 MCP 服务：

- **内置 MCP**（名为 `check-manage`）：平台自带的工具服务，提供数据查询、记忆、轨迹分析等平台工具——AI 助手能「查数据页」「记住偏好」都靠它；
- **外部 MCP**：管理员注册的第三方 MCP 服务（远程 URL 或本地命令），注册后并入 AI 会话的可用工具面。

本页卡片负责：内置 MCP 的**开关与健康探测**、外部 MCP 的**增删改查与启停**。

## 内置 MCP：开关与检测连接

- **检测连接**：点「检测连接」按钮，服务端会直接探测内置 MCP 服务的健康状态，显示可达与否与**延迟**。若 MCP 已宕而会话持续失败，这里就是最先亮红灯的地方。轨迹分析等强依赖内置工具的功能，会在内置 MCP 不可用时明确拒绝而不是静默降级。
- **开关**：关闭后，**之后新建（或清空重置）的会话**不再挂载平台内置工具；已有会话不受影响。关闭前会弹确认框说明后果——数据查询、长期记忆、轨迹分析等能力都会随之不可用，请谨慎操作。

## 注册外部 MCP

1. 在「MCP 服务」卡片点 **添加外部 MCP**，选择类型：
   - **remote**（远程服务）：填写 `url`，可选请求头（headers）；
   - **local**（本地命令）：填写启动命令（argv 列表），可选环境变量（environment）；
2. **名称**必填且全局唯一——它就是会话配置里该服务的标识；不要使用 `check-manage`（平台内置名，外部条目不能遮蔽平台工具）；
3. 提交后可用行上的**启停开关**控制是否并入会话（禁用的条目不进新会话）；
4. 名称、类型、地址均可在行内**编辑**修改。

### 生效边界（重要）

- 外部 MCP 的变更（新增/修改/启停）**只对之后新建或清空重置的会话生效**，已有会话的工作区配置不会被回改；
- 平台**不校验**外部 MCP 目标的可达性——配置错了不会有即时报错，只会在会话内表现为「某个工具不见了」。排查时先回到本卡片核对 url/命令是否正确；健康探测（延迟检测）目前仅对内置 MCP 提供。

## 已知问题

- **删除外部 MCP 服务器当前有已知缺陷**：点删除会失败（后端报错），待修复。在修复前请使用**停用开关**下线不需要的外部服务（停用同样能阻止其进入新会话）。

## 常见问题

**关闭内置 MCP 开关后，老会话还能用平台工具吗？**
能。开关只影响**之后**新建/清空重置的会话；已有会话按创建时的配置继续运行。

**注册了外部 MCP，会话里却看不到它的工具？**
按顺序排查：条目是否**启用**；会话是否是**注册之后新建**的（旧会话不回改）；目标服务是否真的在线（外部条目没有健康探测，需自行确认 url/命令可用）。

**外部服务也想叫 `check-manage`？**
不行。内置条目名是保留名，外部同名条目会被忽略——这是防止外部服务劫持平台工具面的保护机制。

**删除按钮报错？**
已知缺陷（见上节「已知问题」），先用「停用」替代，待版本修复后再删除。
