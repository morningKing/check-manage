# 执行预算与用量

> **对象**：需要控制 AI 批任务成本与规模的管理员、对接批任务开放 API 的外部系统
> **现状**：预算机制**已在引擎侧生效**，但**配置入口尚未开放**（当前没有界面或 API 可配置预算行）——本篇主要说明超限时的行为表现，以及如何在事件流中识别预算事件
> **相关设计**：机制细节见设计文档 `docs/design/ai/03-批任务与执行引擎.md`

---

## 这是什么

执行预算让批任务可以设定**用量上限**（token、成本、墙钟时长、工具调用次数、子代理数等）与**超限处置策略**，防止单个批任务失控消耗。引擎在两个判定点检查预算：子任务认领前、子任务终态时；超限后按策略处置并产生 `budget.exceeded` 事件。

> ⚠️ **当前状态**：预算是**显式启用**的能力——没有预算行就等于不限制。而预算行的**配置入口尚未开放**：界面与对外 API 都没有「设置预算」的入口，普通使用无需任何操作。预算事件与超限处置逻辑已经生效，配置入口属后续版本。

## 预算的维度与限制项

一条预算行挂在某个**作用域**上，当前支持三类维度：

| 维度 | 含义 |
|---|---|
| `batch`（批任务） | 限定单个批任务的全部子任务用量 |
| `user`（用户） | 限定某用户名下会话的累计用量（预留扩展，见下文） |
| `api_key`（API Key） | 限定某把密钥创建的会话的累计用量（预留扩展，见下文） |

每个维度可设这些限制项（均为可选，设了才生效）：

| 限制项 | 含义 |
|---|---|
| `max_tokens` | token 总量上限（输入 + 输出累计） |
| `max_cost` | 成本上限 |
| `max_wall_clock_ms` | 墙钟时长上限 |
| `max_tool_calls` | 工具调用次数上限 |
| `max_subagents` | 子代理委派次数上限 |
| `max_workspace_bytes` | 工作区占用上限 |
| `max_concurrency` | 该批任务同时运行的子任务数上限 |

## 超限策略（on_exceed）

| 策略 | 行为 |
|---|---|
| `warn`（仅告警） | 只记录 `budget.exceeded` 事件，任务继续跑 |
| `drain`（排空后停） | **不再认领新的子任务**（pending 子任务留在队列里不动），正在运行的子任务自然收敛跑完——批次最终停在「部分完成」状态 |
| `abort`（立即中止） | 给该批**全部**待处理与运行中的子任务置「取消请求」，批次整体停下 |

## 引擎在什么时候检查

1. **子任务认领前**：每次 worker 认领子任务时先查预算——已达 `max_concurrency` 的批次本轮不认领；`drain/abort` 策略下 token 或成本已超限的批次不再发新任务。
2. **子任务终态时**：每个子任务跑完，其用量（token/成本/时长等）累计入库后做一次五维判定（tokens/cost/时长/工具调用/子代理数）；超限则写 `budget.exceeded` 事件并执行对应策略。

观测与用量统计都是尽力而为：预算判定本身绝不会打断子任务的正常收口。

**用户 / API Key 维度的现状**：判定逻辑与批维度同口径，但超限动作恒为 `drain` 口径（不会取消其他批任务正在跑的子任务）；当前该判定结果仅记录告警日志，尚未接入认领拦截——同样属于预留扩展，暂无可配置入口。

## 怎么在事件流里识别预算事件

配置了预算的批任务，超限事件出现在**批任务事件流**中：

- 经对外 API 读取：`GET /api/v1/ai-batches/{batchId}/events`（`X-API-Key` 鉴权，见 [AI 批任务 API §11.4](../integration/ai-batch-api.md)）；
- 事件类型为 **`budget.exceeded`**，事件载荷（payload）里带有超限的**维度**（如 tokens/cost）与将要执行的**动作**（warn/drain/abort）；
- 处置动作落地的旁证：`drain` 表现为批次长时间停在「部分完成」、pending 子任务不再推进；`abort` 表现为子任务批量变为「已取消」。出现这类现象而批次没有显式报错时，优先查事件流里有没有 `budget.exceeded`。

## 用量查看

- **对外 API**：批任务详情与结果接口自带 `usage` 汇总字段（`durationMs`/`tokensInput`/`tokensOutput`/`cost`，为全部子任务的累加；单个子任务的结果行里是该子任务自己的用量）。见 [AI 批任务 API](../integration/ai-batch-api.md)。
- **界面**：批任务子任务的执行尝试（Attempt 链）与执行审计页可观察各子任务的执行情况，见 [AI 批任务](./batch-tasks.md) 与 [AI 执行审计](./execution-audit.md)。

## 常见问题

**为什么我在界面上找不到配置预算的地方？**
配置入口尚未开放（当前版本无界面、无 API）。预算机制已生效，但没有预算行就等于不限制——不配置不会有任何行为变化。

**批次一直停在「部分完成」，子任务也不报错，是什么问题？**
若该批任务配置过 `drain` 预算，超限后就是这种表现（运行中的跑完、pending 不再认领）。到事件流确认是否有 `budget.exceeded` 事件；没有预算行的话，再按 [AI 批任务](./batch-tasks.md) 的「待运行」排查路径检查 worker。

**超限后重试失败的子任务，还能跑吗？**
`drain/abort` 超限的批次在用量回落（例如重新配置更高上限）之前，claim 闸会持续拦住新的认领；单纯点「重试失败项」不会绕过预算闸。

**`budget.exceeded` 事件会推送给我的回调吗？**
事件经批任务事件流端点增量读取；完成回调（callback）本身不携带预算事件。对接方式见 [AI 批任务 API](../integration/ai-batch-api.md) 的事件流一节。
