# 01 · 总体架构与运行时

> 本册是 AI 域的架构基座分册：三进程拓扑、AgentRuntime 抽象、per-session workspace 与会话身份、OpenCode 运行时插件、内部契约端点、`opencode serve` 生命周期。机制描述一律以当前代码为准，证据写 `文件:行`（相对 `server/` 或仓库根，见「代码索引」）。全库导航见 [00-总览与功能清单](00-总览与功能清单.md)，架构全景图见 [AI功能架构图](AI功能架构图.svg)。

## 1. 模块职责

AI 域由**三个独立进程**组成，外加一个可选的生产反向代理：

| 进程 | 职责 | 监听 | 代码锚点 |
| --- | --- | --- | --- |
| **Flask 后端** | AI 能力的唯一网关：浏览器只与 Flask 通信，Flask 同时是 **SSE 代理**（把 OpenCode 的每会话事件流逐块转发给浏览器；生产入口 proxy.py 的 SSE 识别名单见 `proxy.py:108-110`）；批任务 worker、看门狗、调度器等后台设施常驻本进程 | `FLASK_PORT`（默认 **3002**，`config.py:40`） | 入口 `app.py:83`（app 工厂）、`app.py:588-589`（`app.run`） |
| **OpenCode serve** | **Agent 运行时**：会话/消息/子代理编排、工具调用、SSE 事件流的真正生产者；调用外部 LLM Provider 完成推理 | `OPENCODE_BASE_URL`（默认 `http://127.0.0.1:4096`，`config.py:87`；`opencode_global.serve_port` 取 URL 端口、缺省 4096，`opencode_global.py:870-873`） | 客户端 `opencode_client.py:27` |
| **MCP Server** | 平台**工具面**：把集合查询、文件读取、产物落盘、数据写、长期记忆等平台能力暴露为 27 个 MCP 工具（注册表 `mcp-server/tools/__init__.py:20-49`），供 OpenCode 会话内调用 | `MCP_PORT`（默认 **3003**，`mcp-server/app_config.py:20`） | 入口 `mcp-server/main.py:57-97` |

边界事实：

- **浏览器只与 Flask 通信**。前端不直连 OpenCode（4096）也不直连 MCP Server（3003）；生产部署下浏览器访问的是 `proxy.py`（默认 8080），它把 `/api/*` 反代到 Flask（`proxy.py:131-137`），静态资源与 SSE 均经它中转（`proxy.py:108-110`）。
- **OpenCode 不直接触碰业务数据**——它只会话编排与工具调度；平台数据的读写全部经由 MCP 工具回到 Flask/DB。
- **MCP Server 的身份不来自网络位置，而来自 token**：每个 MCP 请求带会话级 `?token=`，MCP 侧 `context_from_token` 直查 DB（`ai_chat_sessions` JOIN `users`）得到 `(session_id, user_id, role)`（`mcp-server/main.py:25-41`、`mcp-server/auth.py:19-46`），RBAC 由 `rbac.tool_allowed`/`is_readonly` 按角色过滤工具面（`mcp-server/tools/__init__.py:62-84`）。

## 2. 模块组成

### 2.1 进程启动编排（单源：`utils/opencode_launch.py`）

`opencode serve` 的**启动方式只有一处定义**：`opencode_launch.py` 刻意零依赖（不 import flask/db，`opencode_launch.py:1-20`），proxy.py 与 Flask 侧的重启编排共用同一份真源：

- `serve_launch()` 返回 `(target, use_shell)`：默认 `[opencode, serve]` argv 形式；`OPENCODE_SERVE_CMD` 整串覆盖时才走 shell（`opencode_launch.py:48-57`）。
- `serve_cwd()` 默认 `~`——中性目录，避免误拾取项目级 `.opencode/`（`opencode_launch.py:43-45`）。
- `child_env()` 给子进程钉死 UTF-8 执行环境（`PYTHONUTF8=1`/`PYTHONIOENCODING=utf-8`/`LANG`/`LC_ALL`），解决 Windows 中文环境 GBK 乱码（`opencode_launch.py:77-99`）。
- `serve_env()` = `child_env()` + **显式**传入 `OPENCODE_GLOBAL_DIR`（`.env` 只被 Python 侧 load_dotenv 读入，不会自动出现在子进程环境里）+ `BAIZE_INTERNAL_TOKEN`（插件用）+ 工具超时三变量（`opencode_launch.py:102-121`）。
- `autostart_enabled()`：`OPENCODE_AUTOSTART` 默认开（`opencode_launch.py:66-67`）。

生产入口 `proxy.py` 按序拉起并探测三个子进程：backend（waitress，`proxy.py:334-370`）→ MCP（独立 venv 的 `mcp-server/main.py`，`proxy.py:423-440`）→ `opencode serve`（`proxy.py:468-497`），随后发现 serve 监听 PID 写入归属登记（`record_serve_ownership`，`proxy.py:499-524`；主流程 `proxy.py:536-596`）。serve 已被外部（手工/服务管理器）拉起时不重复启动、不接管（`proxy.py:469-476`）。

### 2.2 AgentRuntime 抽象（`utils/runtime/`）

上层执行引擎**不得直接依赖 OpenCode 客户端**，统一经 `AgentRuntime` 抽象（`runtime/__init__.py:1-7`、`runtime/base.py:16`）。接口契约 **7 个方法**（`runtime/base.py:20-41`）：

| 方法 | 语义 |
| --- | --- |
| `capabilities()` | 能力声明：checkpoint / pause / network_isolation …（`runtime/base.py:20-22`） |
| `create_session(directory, title)` | 在指定 workspace 目录建 OpenCode 会话，返回 OC 会话 id（`runtime/base.py:24`） |
| `dispatch(oc_session_id, prompt, *, directory, agent, model)` | 异步派发一轮 prompt（`runtime/base.py:27-29`） |
| `list_messages(oc_session_id, directory)` | 拉消息列表（批 worker 的完成判定消费 `info.finish`/`info.time.completed`；`runtime/base.py:31`） |
| `get_messages(oc_session_id, directory)` | 同上但不吞请求异常（`runtime/base.py:34`） |
| `abort(oc_session_id, directory)` | 中断在途回合（`runtime/base.py:37`） |
| `health()` | 健康探测（`runtime/base.py:40`） |

实现方（Phase E 的 Docker/Job 运行时）必须保证四条硬语义（`runtime/base.py:3-8` docstring）：**进程树可整体 kill（不留孤儿）、网络默认拒绝按 allowlist 放开、secret 临时注入不落 workspace、退出后 attempt 必须收敛**。能力不满足时抛 `RuntimeCapabilityError`（`runtime/base.py:11-12`）。

**运行时切换**：环境变量 `AI_AGENT_RUNTIME` 选择实现，当前**仅 `opencode_local` 可用**；`stub` 为压测保留；其余值直接抛 `RuntimeCapabilityError`（`runtime/__init__.py:23-29`）。

- `OpenCodeLocalRuntime`：包装既有 `OpenCodeClient`，行为与 batch_engine 的 `_OpenCodeFacade` 逐字节一致；`capabilities()` 如实声明 `network_isolation: False`、`process_tree_kill: False`（本地进程做不到，留给 Phase E）（`runtime/opencode_local.py:14-19`）；`get_client()` 是引擎取底层客户端的公开接线点（`runtime/opencode_local.py:26-33`）；`health()` 用 `list_agents` 探活（`runtime/opencode_local.py:62-67`）。
- `StubRuntime`：**压测容量层专用**——内存态模拟 agent 生命周期，消息形状与 `opencode_client.get_messages` 原始返回逐字段对齐（完成判据 `info.finish` 非 `tool-calls` 且 `info.time.completed` 存在），profile 由 `AI_STUB_PROFILE` 注入延迟/错误率/挂起率（`runtime/stub.py:1-26,116-153`）。压测口径详见分册 11（`11-容灾稳定性与压测.md`）。

### 2.3 OpenCode 客户端（`utils/opencode_client.py`）

对 `opencode serve` HTTP API 的薄封装（对码版本 v1.2.26，`opencode_client.py:1`）。要点：

- **会话绑定目录靠 `?directory=` 查询参数**，body 里的 `cwd`/`directory` 被 OpenCode 忽略（`opencode_client.py:4-5`）；每个会话的 workspace 目录唯一，因此 per-directory 事件流即会话事件流（`opencode_client.py:317-329`）。
- `create_session` 用 `max(timeout, 120)` 的宽超时——冷目录首次初始化会触发 OpenCode 后台装插件，可达 60-90s（`opencode_client.py:38-47`）。
- `send_prompt_async`：model 必须显式传 `"<providerID>/<modelID>"`（OpenCode 不读 opencode.json 的 `model` 字段做 prompt 选择）；`agent` 选本轮主 agent；`agent_parts` 把 `@name` 提及转成 `{type:'agent'}` part 委托子代理（`opencode_client.py:84-119`）。
- 完成信号是**确定性的**：`GET /session/{id}/message` 的 `info.finish` + `info.time.completed`，不是易竞态的 `session.idle` 一次性事件（`opencode_client.py:68-74`）。
- 交互辅助面：providers/commands/skills/agents 列表、`/command`、`/summarize`（上下文压缩）、question 应答、permission 审批（request_id 白名单校验+percent-encode 防路径注入，`opencode_client.py:275-287`）、MCP/LSP/formatter 状态、SSE 订阅（`opencode_client.py:141-357`）。

### 2.4 运行时插件（随 Flask 启动自动部署进 OpenCode）

三个插件 + 一个判官 agent 定义，随 Flask 启动写入 `<OPENCODE_GLOBAL_DIR>/plugin/`（幂等，内容无变化不重写）；**OC serve 在启动时加载 plugin 目录——部署后需重启 serve 才生效**：

| 插件 | 部署调用 | 机制 | 生效钩子 |
| --- | --- | --- | --- |
| `baize-trace.js`（SkillOpt 运行时轨迹 + PreToolUse 门禁执行器） | `app.py:182-191` → `skillopt.ensure_runtime_plugin`（`utils/skillopt.py:367-397`，插件名 `utils/skillopt.py:26`） | 上报 skill load/invoke 与 `session.idle` 事件到 `POST /ai/memory/internal/runtime-events`；每次工具调用前 POST `POST /ai/gate/internal/pre-check`，命中 deny list 即抛错阻断该次调用（`utils/skillopt.py:247-364`） | `event` + `tool.execute.before` |
| `baize-subagent-reuse.js`（子代理会话复用） | `app.py:206-212` → `subagent_reuse_plugin.ensure_subagent_reuse_plugin`（`utils/subagent_reuse_plugin.py:171-196`） | `task` 工具 **before**：按（父会话, subagent_type）查平台钉住的 task_id 并**强制覆盖**模型入参（模型常回显/编造旧 id，平台 pin 权威）；**after**：从工具输出解析 `task_id: ses_xxx`（兜底 part metadata.sessionId），回调 `/pins` 登记。回调带 3s 超时+1 次重试+进程内 120s 缓存兜底；负判定只固化「确定性拒绝」（`not_enabled`/`no_agent`），`unresolved` 不缓存（`utils/subagent_reuse_plugin.py:21-162`） | `tool.execute.before/after` |
| `baize-tool-timeout.js`（内置工具超时看门狗） | `app.py:225-232` → `tool_timeout_plugin.ensure_tool_timeout_plugin`（`utils/tool_timeout_plugin.py:138-166`） | 给**每一次**内置工具调用挂墙钟看门狗：默认 900s（`OPENCODE_TOOL_TIMEOUT_MS`，`utils/tool_timeout_plugin.py:41`）超时调 `client.session.abort` 中断**整回合**——OpenCode 没有"取消单个工具"的 API；豁免名单默认 `task`（子代理委派合法耗时长，批任务侧有更聪明的存活检测看门狗）。`session.deleted` 事件清理泄漏计时器，防止对已删会话误 abort（`utils/tool_timeout_plugin.py:44-127`）。背景：OC 内置工具仅 bash（120s/上限 600s）与 webfetch（30s/120s）自带门限，read/grep/glob/edit/write/task 及 MCP 调用**没有任何超时**，卡死工具在交互会话里会永远挂着（`utils/tool_timeout_plugin.py:21-24`） | `tool.execute.before/after` + `event` |
| 判官 agent（动作门禁 verifier） | `app.py:216-220` → `utils.verifier.ensure_verifier_agent` | 部署 OpenCode 子代理定义供核对期使用（属分册 05 口径） | agent 定义文件 |

插件进程内直连 Flask 网关最短路径，端点随 `FLASK_PORT` 拼装（`app.py:183-191`）；token 走 serve 进程 env `BAIZE_INTERNAL_TOKEN`（由 `opencode_launch.serve_env` 从 `MCP_INTERNAL_TOKEN` 透传，`opencode_launch.py:107-112`），env 缺失时回落插件文件里安装时嵌入的 token。

### 2.5 管理面：OpenCode 全局配置区（`utils/opencode_global.py`）

管理页「OpenCode 运行时」直接编辑 serve 从全局配置目录**启动时**加载的文件：`<OPENCODE_GLOBAL_DIR>/skill/<name>/SKILL.md`、`<OPENCODE_GLOBAL_DIR>/agent/<name>.md`（`opencode_global.py:1-7`；目录默认 `~/.config/opencode`，`config.py:126-128`）。安全与写路径约束（名称字符集白名单、`resolve_under` realpath 包含性检查防符号链接逃逸、原子写、单文件 1 MiB/总量 64 MiB 上限）见 `opencode_global.py:59-62,126-194`。文件视图与 serve 活视图合并出 `runtime` 状态（`loaded`/`pending`/`serveOffline`/`disabled`，`opencode_global.py:743-837`）；受管配置树的确定性哈希 `config_generation()` 供 UI 对账（`opencode_global.py:881-912`）。技能/agent 的 CRUD 语义属分册 08。

## 3. 数据模型

本册涉及的状态载体（表结构细节归各分册）：

- **会话身份**：`ai_chat_sessions.session_token`（urlsafe base64、32 字节熵 ≈43 字符）+ `token_expires_at`（`session_token.py:1-4`）。生成 `generate_token`（写 token+过期时间，`session_token.py:12-23`）、续期 `renew_token`（只推 `token_expires_at` 并触 `last_active_at`，`session_token.py:26-33`）、吊销 `revoke_token`（`status='revoked'`+过期时间归零，`session_token.py:38-46`）。MCP 侧校验要求 `status='active'` 且未过期（`mcp-server/auth.py:28-43`）——吊销后 token 立即失效。
- **每会话 workspace 目录**：`<AI_WORKSPACE_ROOT>/<user_id>/<session_id>/`（`workspace.py:67-68`；根默认 `~/.check-manage/ai-workspaces`，`config.py:83-85`），内含 `uploads/`（用户输入）、`outputs/`（产出）、自动 `git init` 的根仓库（`.gitignore` + 初始提交，供「变更文件」面板，`workspace.py:27-38,134-175`）、`AGENTS.md`（告诫 agent 拉远端代码要 clone 进子目录、不得动根 `.git`，`workspace.py:45-60`）、`opencode.json`（per-session MCP 身份，见 §4）。批任务暂存区在 `<root>/batch-staging/<user_id>/<upload_session_id>/`（`workspace.py:426-444`）。
- **serve 归属登记**：`~/.check-manage/opencode-runtime/serve-ownership.json`（`OPENCODE_RUNTIME_DIR` 可覆盖，`opencode_ownership.py:38-46`），内容 `{pid, port, owner:'platform', recorded_at}`（`opencode_ownership.py:49-67`）；backend 与 proxy.py 两个进程经它共享一份真源。PID 重用靠"记录的 PID 仍在该端口监听"兜底（`opencode_ownership.py:14-22`）。
- **子代理复用意图**：`ai_subagent_internal.py` 进程内字典 `_INTENT`（callID → (root_session_id, agent, ts)），TTL 600s（`ai_subagent_internal.py:33-44`）；钉住值落 `ai_subagent_pins` 表（`(root_session_id, agent)` 唯一，UPSERT，`ai_subagent_internal.py:160-171,180-195`；表归分册 04）。
- **长期记忆**：mem0 + Chroma，存 `~/.check-manage/mem0`（`server/utils/memory.py:17`）；Flask 是 mem0 实例的**唯一持有者**（Chroma 是单写者存储，`server/utils/memory.py:1-3`），全部 mem0 调用钉在单线程 executor 上（onnxruntime 原生亲和，`server/utils/memory.py:23-51`）。

## 4. 核心流程

### 4.1 会话创建与身份链路（五步）

1. **浏览器 → Flask**：`POST /ai/chat/sessions`（JWT 鉴权 `@write_required`，`routes/ai_chat.py:119-121`）。Flask 建 workspace 目录（`routes/ai_chat.py:123-125` → `workspace.create_session_workspace`）。
2. **Flask 签发 opaque 会话 token**：先插 `ai_chat_sessions` 行再经 `session_token.generate_token` 覆写（TTL `AI_SESSION_TTL_HOURS` 默认 24h；`routes/ai_chat.py:131-143`、`config.py:89`）。
3. **Flask 写 per-session `opencode.json`**：`mcp_url = f"{MCP_SERVER_URL}/mcp?token={token}"`，连同模型、外部 MCP 合并项写入 workspace（`routes/ai_chat.py:146-150` → `workspace.write_opencode_config`，`workspace.py:288-323`）。**这是 per-session MCP 身份的唯一机制**——OpenCode 没有 per-session MCP API，只有 per-directory 配置（`workspace.py:1-7` docstring）；平台条目名固定 `check-manage`（`routes/ai_chat.py:78`），外部注册项不得遮蔽它，管理端关闭内部 MCP 时整个平台条目不写（`workspace.py:304-314`）。
4. **OpenCode → MCP Server**：Flask 调 `client.create_session(directory=workspace_path)` 让 OC 会话绑定该目录（`routes/ai_chat.py:160-162`）；此后会话内每次工具调用，OpenCode 按 workspace 里的 `opencode.json` 连 MCP，请求带 `?token=`。MCP 侧 `TokenMiddleware` 先把无效 token 挡在门外（401，`mcp-server/main.py:60-78`），`_resolve_context` 再从 request context 取 token 查 **DB**（`mcp-server/main.py:25-41` → `mcp-server/auth.py:19-46`：`ai_chat_sessions` JOIN `users`，要求 active+未过期）得到 `(session_id, user_id, role)`。
5. **查表 → RBAC**：工具按 `ToolContext.role` 过滤（`mcp-server/tools/__init__.py:62-84`）；**数据写**不直连 DB——经 `POST /ai/data-internal/execute` 回到 Flask，由 Flask 以该用户签发的 JWT 走**真实应用层路由**，字段校验/权限/工作流/审计与 UI 操作完全同路（`mcp-server/tools/_data_api.py:1-13,64-80`、`routes/ai_data_internal.py:1-12`）。

token 续期发生在会话活跃时（`renew_token`），吊销即断 MCP 身份。会话恢复场景（OC 会话 id 失效）由 `session_history.render_history_block` 把近 6 轮对话渲染成纯文本摘要注入新会话首条 prompt（`session_history.py:19-59`）。

### 4.2 workspace 变更与产出（Flask 侧渲染，不走 OpenCode diff）

- **变更文件**：OpenCode 原生 `/session/{id}/diff` 对 clone+edit 流返回空，平台直接读 workspace 里各 git 仓库的 `git status`（`workspace_changes.py:1-13`）。扫描 workspace 内有界深度的 git 仓库（根仓库 + 嵌套 clone，`workspace_changes.py:64-82`）；无基线提交的拉取仓做一次性 baseline commit，让后续只显示真实修改（`workspace_changes.py:217-250`）；500 条上限 + 次要文件（锁文件/构建产物）降权排序（`workspace_changes.py:20-27,143-154`）。
- **产出文件**：`workspace_outputs.list_session_files` 递归扫 workspace（跳过 uploads/.git/噪声目录与 dotfiles，上限 1000 条），分类 uploads/outputs/workspace（`workspace_outputs.py:15-66`），再由 `augment_with_data_file_id` 单条 SELECT 关联 `ai_chat_session_files`（`workspace_outputs.py:69-91`）。

### 4.3 会话内容持久化（服务端守护，独立于浏览器 SSE）

`chat_persist.py` 为每个活跃会话起守护线程订阅 OpenCode 的 per-directory 事件流，在 `session.idle` 落库整轮助手消息，流中每 1s 增量落一次（切换会话不丢工具调用/半截输出；`chat_persist.py:1-28,755-781`）。part→落库内容的映射统一在 `opencode_parts.map_part`（text/reasoning/tool/subtask→`subtask_use` 占位，`opencode_parts.py:17-82`），实时聊天与批引擎两条持久化路径共用同一份实现；OC 七类 `AssistantMessage.error` 的格式化也共用 `format_opencode_error`（`opencode_parts.py:85-99`）。断流恢复用 `backfill_from_rest` 从 REST 补齐（`chat_persist.py:465-512`）。

### 4.4 `opencode serve` 生命周期

**归属分类**（`opencode_ownership.status`，`opencode_ownership.py:91-126`）：

| mode | 判定 | 处置 |
| --- | --- | --- |
| `none` | 端口无人监听 | 可安全拉起 |
| `platform` | 登记的 PID 仍在该端口监听 | 平台可 kill/重启 |
| `external` | 有监听但登记的是别的进程 | **绝不代杀**（服务管理器/他人实例） |
| `unknown` | 有监听但无登记文件（升级后首跑/登记被删） | 按 external 处理：**拒杀而非猜测** |

**重启编排**（管理页手动与看门狗自动共用，`opencode_global.py:960-1057`）：持 `RESTART_LOCK` 互斥（`opencode_global.py:47-56`）→ 按端口找 LISTEN PID，`platform_owned` 为假即抛 `EXTERNAL_PROCESS` 409 拒绝（`opencode_global.py:986-995`）→ kill 后经 `opencode_launch.serve_launch/serve_env` 重新拉起（显式钉 `OPENCODE_GLOBAL_DIR`，`opencode_global.py:999-1012`）→ 轮询 `/global/health` 至恢复，发现新监听 PID 立即 `ownership.record`（健康通过后仍短暂补发现，避免下一次重启因未登记而误判 external，`opencode_global.py:1014-1052`）。重启前 `active_workload()` 统计会被打断的批次子会话/交互会话/活跃批次（`opencode_global.py:844-867`）。

**看门狗**（`utils/oc_watchdog.py`）：APScheduler 每 `AI_OC_WATCHDOG_INTERVAL_SEC`（默认 30s，0=关）探测一次 `serve_health()`，**连续 `AI_OC_WATCHDOG_THRESHOLD`（默认 2）次不可达**才调 `restart_serve()`（`oc_watchdog.py:35-36,69-133`）。多进程部署用 `execution_lease` 租约 `lease_kind='oc-watchdog'` 互斥，只有值班进程真正工作（`oc_watchdog.py:11-13,146-158`）；与手动重启共锁互跳（`oc_watchdog.py:14-16,105-107`）；端口被外部进程占用时标记后永不代杀，等人工（`oc_watchdog.py:101-103,118-124`）。恢复动作只拉起进程，不自动重放失败批任务（副作用重试属恢复决策/人工职责，`oc_watchdog.py:17-19`）。启动接线在 `app.py:559-564`；状态在管理页 `/ai/opencode/overview` 的 watchdog 字段可见（`oc_watchdog.py:24`）。

**配置生效语义**（对码 OpenCode **v1.15.1**，spike-tested 2026-09-13，`opencode_global.py:9-14`）：

- **没有 CRUD HTTP API、没有热重载**：文件写入对运行中的 serve 不可见，`PATCH /global/config` 也不触发重载。**重启 serve 是唯一生效途径**，所以每个受管条目都带按活视图 diff 出的 `runtime` 状态（`loaded`/`pending`）。
- 技能名必须与目录名一致；SKILL.md 缺 `description` 会被 OpenCode 静默过滤，写入侧强制非空（`opencode_global.py:17-19,342-355`）。
- `GET /skill` 的 `location` 字段是"文件已被加载"的权威信号；`GET /agent` 无路径字段，按名字匹配（`opencode_global.py:20-22`）。

### 4.5 每会话 workspace 的重置/清理/回收

- `reset_session_workspace`：批任务「重新执行」用——uploads 先备份到工作区外，整目录删除（Windows 只读 git objects 经 `_rm_force` chmod 重试）后按新建同径重建骨架，uploads 原样移回；**不重写 opencode.json**（批子会话本就没有该文件，凭空写入无效 token 反而破坏 MCP）（`workspace.py:178-247`）。
- `cleanup_session_workspace` / `cleanup_batch_workspaces`：best-effort 拆除，统一根+legacy 根都扫（`workspace.py:250-285`）。
- `reclaim_expired_workspaces`：每日作业回收超保留期的终态批次子会话工作区（只清目录不动 DB 行）（`workspace.py:478-518`）。
- 批任务派发时 `ensure_batch_permissions` 给子会话 workspace 补 `permission.external_directory: "allow"`——否则无人值守会话读工作区外文件触发授权询问、无人应答即无限挂起（`workspace.py:326-359`）。

## 6. 依赖与协作关系

- **Flask → OpenCode**：全走 `OpenCodeClient`（经 `get_runtime()` 抽象）；交互聊天的 SSE 转发、批引擎的轮询完成判定、管理页的重启/健康探测都是这条通道的消费者。
- **OpenCode → Flask**（三条回调，全部 `X-Internal-Token`）：① 插件上报/runtime-events 与 pre-check（`/ai/memory/internal/runtime-events`、`/ai/gate/internal/pre-check`）；② 子代理复用三回调（`/ai/subagent-internal/*`）；③（经 MCP 中转）数据写（`/ai/data-internal/execute`）。
- **OpenCode → MCP Server**：per-directory `opencode.json` 驱动，`?token=` 会话身份；工具面 27 个（分册 02/03/04/05/06/09 各认领其子集）。
- **MCP Server → Flask**：memory 三工具（`memory_client`）与数据写（`_data_api`），即 §5.1 的内部契约端点。
- **MCP Server → DB**：只读直连（query_collection/collection_resolve 等既有通道）；**写不直连**。
- **proxy.py → 三进程**：拉起与探测；AI 形态的 SSE（`/api/ai/chat/.../events` 等）必须逐块中转，新增 SSE 路由要同步 `_is_sse()` 名单否则生产被缓冲挂死（`proxy.py:108-110`）。
- **后台设施**（Flask 进程内，`WERKZEUG_RUN_MAIN` 守卫防 reloader 双启，`app.py:533-577`）：批 worker、扫描调度、看门狗、outbox 投递器、编排调度器——多实例互斥统一走 `utils/execution_lease` 租约（分册 03/11）。

## 7. 设计决策

1. **浏览器只与 Flask 说话**：OpenCode/MCP 绑 127.0.0.1，浏览器零直连——鉴权、限流、审计、SSE 语义都收口在网关一层（`AI功能架构图.svg` 底注、`proxy.py` 反代设计）。
2. **per-directory `opencode.json` 承载 per-session MCP 身份**：OpenCode 无 per-session MCP API，这是唯一机制（`workspace.py:1-7`）；代价是 token 落在 workspace 文件里，故 workspace 按 `user_id/session_id` 两级隔离、`safe_resolve` 拒绝绝对路径与越界（`workspace.py:362-377`），`AI_WORKSPACE_ROOT` 刻意让会话工作区互不可见（`config.py:80-85`）。
3. **AgentRuntime 抽象先行、本地实现如实声明短板**：`opencode_local` 承认 `network_isolation/process_tree_kill = False`，把容器化运行时的硬语义（kill 整树/默认拒网/secret 不落盘）写进接口契约留给 Phase E（`runtime/base.py:3-19`、`runtime/opencode_local.py:17-19`）。
4. **重启即生效（v1.15.1 无热重载）**：不做半吊子的进程内补丁，而是把"文件视图 ∪ 活视图"的 `runtime` 状态、`config_generation` 哈希、重启互斥与 workload 预警做成显式管理面（`opencode_global.py:9-14,743-837,881-912`）。与旧文档差异：旧「OpenCode运行时依赖与部署」描述的部分热更新路径在 v1.15.1 已不成立，以本节为准。
5. **外部进程永不按端口杀**：重启历史上曾"杀端口上的一切"，现以 ownership 登记收敛为 platform/external/unknown 分类，unknown 拒杀走安全侧（`opencode_ownership.py:1-22,91-126`）；看门狗同样绝不误杀外部实例（`oc_watchdog.py:101-103`）。
6. **fail-open 只给门禁，白名单只给写转发**：pre-check 不可达放行（可用性优先、终态核对兜底，`ai_gate_internal.py:11-14`）；数据写恰恰相反——白名单外一律 403、保留路径拒绝、强制走真实路由（`ai_data_internal.py:10-12,41-52`）。两条内部通道的失败语义方向相反，是刻意的。
7. **插件部署与 serve 加载解耦**：Flask 启动只负责把插件文件写进全局目录（幂等、失败不阻断启动，`app.py:174-232` 各 try 块），加载时机属 serve 重启编排（§4.4）。
