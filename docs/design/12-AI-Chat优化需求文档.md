## 1. 文档概述

### 1.1 背景

平台 AI 对话助手（`AiChatView`）已具备流式响应、工具调用、子任务链路、长期记忆、Slash 命令、上下文压缩等核心能力，但与 Claude Code TUI 的成熟体验相比，在**上下文感知、文件引用、安全审批、交互细节**等维度仍有明显差距。本文档梳理 Top 10 优先级最高的优化点，给出功能说明、交互设计与验收标准。

### 1.2 目标

- 让用户对**上下文余量、API 成本**有显式感知，避免"突然超限"
- 补齐**文件引用、图片输入**等高频交互缺口
- 引入 **Plan 模式 + Diff 审批**，提升 Agent 自主操作的可控性
- 优化长任务/长消息场景下的可读性与可达性

### 1.3 范围与优先级矩阵

| # | 功能 | 优先级 | 工作量 | 依赖 |
|---|------|--------|--------|------|
| F1 | Token 用量与上下文水位线 | 高 | 中 | OpenCode 事件提供 token usage |
| F2 | @-mention 文件路径与自动补全 | 高 | 中 | 工作区文件树接口 |
| F3 | Diff 审批/拒绝 | 高 | 大 | F2（可选）、git 回滚工具 |
| F4 | 流式自动滚动控制 | 高 | 小 | 无 |
| F5 | Plan 模式 | 高 | 大 | OpenCode plan agent 配合 |
| F6 | 会话搜索 | 高 | 中 | 全文索引 |
| F7 | 图片粘贴与拖拽上传 | 中 | 小 | 多模态模型支持 |
| F8 | 工具权限管理 | 中 | 中 | 会话级配置存储 |
| F9 | 长任务完成通知 | 中 | 小 | Notification API |
| F10 | 消息折叠 | 中 | 小 | 无 |

## 2. 功能需求详述

### F1. Token 用量与上下文水位线

#### 2.1.1 背景与痛点

当前用户对会话累计 token、上下文窗口占用**完全无感知**，往往等到模型返回 "context too long" 错误才发现超限。Claude TUI 在底部状态栏实时显示 `Context: 45%`，并在接近上限时主动提示用户 `/compact`。

#### 2.1.2 功能描述

在会话底部状态栏展示**当前会话累计 token 数**与**上下文窗口占用百分比**，并按阈值变色提示；接近上限时主动弹出压缩建议。

#### 2.1.3 详细需求

1. **Token 来源**：OpenCode SSE 事件中的 `message.updated` / `session.idle` 携带 `usage` 字段（prompt_tokens / completion_tokens / total_tokens）。若无，则由后端按消息内容估算（字符数 / 4 近似）。
2. **展示位置**：输入框上方常驻状态条，格式：`模型: claude-3.5 ｜ 上下文: 12.3k / 200k (6%) ｜ 累计: 45.6k`。
3. **水位线阈值**：
   - `< 70%`：默认色（灰）
   - `70% ~ 90%`：警告色（橙）
   - `> 90%`：危险色（红）+ 弹出气泡提示「上下文接近上限，建议压缩」并带「立即压缩」按钮
4. **累计 token**：跨会话所有回合的 total_tokens 累加，用于成本感知。
5. **持久化**：每会话累计 token 存入 `ai_chat_sessions` 新增字段 `total_tokens`（int，默认 0），每次 idle 时增量更新。

#### 2.1.4 交互设计

```
┌──────────────────────────────────────────────────┐
│ 模型: anthropic/claude-3.5-sonnet ▾  上下文: 6%  │  ← 状态条
├──────────────────────────────────────────────────┤
│                  消息列表区                       │
└──────────────────────────────────────────────────┘
                          ┌─────────────────────┐
                          │ ⚠ 上下文已达 92%   │  ← 超阈值气泡
                          │ [立即压缩] [稍后]  │
                          └─────────────────────┘
```

#### 2.1.5 预期效果

- 用户随时知道还剩多少上下文可用
- 接近上限前主动引导压缩，杜绝"突然超限报错"
- 累计 token 给出成本感知，为后续配额管控打基础

#### 2.1.6 验收标准

- [ ] 每条助手消息 idle 后，状态条 token 数值刷新
- [ ] 上下文百分比按 `累计 token / 模型 max_context` 计算
- [ ] 达 90% 时弹出压缩建议气泡
- [ ] 会话切换时状态条数值正确切换
- [ ] 刷新页面后累计 token 从 DB 恢复

#### 2.1.7 涉及代码

- 后端：[ai_chat.py](../../server/routes/ai_chat.py#L380-L481) `send_message` / `sse_proxy` 解析 usage
- 持久化：[chat_persist.py](../../server/utils/chat_persist.py#L315-L380) `persist_turn` 写入 token
- 前端状态：[aiChat.ts](../../src/stores/aiChat.ts#L44-L89) 新增 `tokenBySession`
- 前端 UI：[AiChatView.vue](../../src/views/ai-chat/AiChatView.vue) 输入框上方新增状态条

### F2. @-mention 文件路径与自动补全

#### 2.2.1 背景与痛点

当前 `@` 仅支持 mention Agent（[agentMentions.ts](../../src/utils/agentMentions.ts)）。用户想引用工作区文件作为上下文时，只能先上传附件，无法在消息文本中直接 `@src/main.ts` 引用。Claude TUI 支持 `@文件路径` 直接将文件内容注入上下文。

#### 2.2.2 功能描述

在输入框中输入 `@` 后，除了展示 Agent 列表，同时展示**当前会话工作区的文件树**，支持路径模糊搜索补全；选中后在消息中插入 `@相对路径` 标记，发送时后端将文件内容内联到 prompt。

#### 2.2.3 详细需求

1. **触发**：输入 `@` 后触发补全 palette，palette 分两组：
   - 「智能体」组：现有 Agent 列表
   - 「文件」组：工作区文件树（含 outputs/、uploads/、根目录文件）
2. **文件树来源**：复用 `GET /ai/chat/sessions/:id/files` 列表，或新增 `GET /ai/chat/sessions/:id/file-tree` 返回扁平化路径列表（含目录节点）。
3. **模糊搜索**：输入 `@main` 时按子串匹配过滤文件路径，最多展示 20 条。
4. **插入格式**：选中文件后插入 `@uploads/data.csv`（相对路径），与 Agent mention 视觉一致（chip 样式）。
5. **后端处理**：`send_message` 解析消息中的 `@路径` 标记，读取文件内容内联到 prompt（逻辑复用现有 `_read_text_attachment`），二进制文件则提示 Agent 可用工具读取。
6. **展示**：发送后的用户消息气泡中，`@文件路径` 渲染为可点击的 chip，点击打开文件预览抽屉。

#### 2.2.4 交互设计

```
输入：帮我分析 @data            ↓ 触发补全
┌──────────────────────────────┐
│ 智能体                        │
│  @build      构建助手         │
│  @explore    探索助手         │
│ 文件                          │
│  @uploads/data.csv           │
│  @outputs/report.json        │
│  @src/utils/helper.ts        │
└──────────────────────────────┘
```

#### 2.2.5 预期效果

- 用户无需离开输入框即可引用工作区文件
- 文件内容自动注入上下文，Agent 无需调用 read 工具
- 减少往返轮次，提升效率

#### 2.2.6 验收标准

- [ ] `@` 触发的 palette 包含文件组
- [ ] 输入 `@xxx` 时按子串过滤文件
- [ ] 选中后插入 `@相对路径` chip
- [ ] 发送后后端正确内联文件内容到 prompt
- [ ] 用户气泡中 `@路径` 可点击预览
- [ ] 二进制文件不内联，提示 Agent 用工具读取

#### 2.2.7 涉及代码

- 前端 mention 解析：[agentMentions.ts](../../src/utils/agentMentions.ts) 扩展或新增 `fileMentions.ts`
- palette：[CommandPalette.vue](../../src/components/ai-chat/CommandPalette.vue) 增加文件分组
- 后端：[ai_chat.py](../../server/routes/ai_chat.py#L380-L481) `send_message` 解析 `@路径` 标记
- 文件树：复用 [workspace_outputs.py](../../server/utils/workspace_outputs.py) `list_session_files`

### F3. Diff 审批/拒绝

#### 2.3.1 背景与痛点

当前 AI 修改工作区文件后，前端仅在「变更文件」面板展示 diff（[FileDiffView.vue](../../src/components/ai-chat/FileDiffView.vue)），**只读、无审批动作**。Agent 可自由写入/删除文件，存在安全风险。Claude TUI 每次文件修改需用户确认 accept/reject。

#### 2.3.2 功能描述

在 diff 展示基础上，为每个变更文件增加 **「接受」「拒绝（还原）」** 按钮；接受则保留变更，拒绝则用 `git checkout` 还原该文件。支持「全部接受」「全部拒绝」批量操作。

#### 2.3.3 详细需求

1. **审批状态**：每个变更文件新增状态 `pending` / `accepted` / `rejected`，存于会话工作区 `.changes.json` 或后端内存。
2. **接受**：标记 `accepted`，保留文件当前内容。
3. **拒绝**：标记 `rejected`，执行 `git checkout -- <file>` 还原（新增文件则 `git rm` 或直接删除）。
4. **批量操作**：变更面板顶部「全部接受」「全部拒绝」按钮。
5. **未审批阻塞**：可选配置——未审批的变更在下一回合发送前弹出确认（避免未审变更被后续操作覆盖）。
6. **审计**：审批动作记录到 `ai_chat_audit_log`（用户、会话、文件、动作、时间）。

#### 2.3.4 交互设计

```
┌─ 变更文件 (3) ──────────────────────────────┐
│ [全部接受] [全部拒绝]            刷新        │
├──────────────────────────────────────────────┤
│ M  src/main.ts          [接受] [拒绝]        │
│ A  outputs/report.csv   [接受] [拒绝]        │
│ D  temp/cache.json      [接受] [拒绝]        │
└──────────────────────────────────────────────┘
```

#### 2.3.5 预期效果

- 用户对 AI 的文件修改有显式控制权
- 可拒绝不想要的变更，避免误操作
- 审计轨迹可追溯

#### 2.3.6 验收标准

- [ ] 每个变更文件有接受/拒绝按钮
- [ ] 拒绝 modified 文件后 `git checkout` 还原
- [ ] 拒绝 added 文件后删除
- [ ] 全部接受/拒绝正确批量执行
- [ ] 审批状态刷新页面后恢复
- [ ] 审批动作写入审计日志

#### 2.3.7 涉及代码

- 前端 diff：[FileDiffView.vue](../../src/components/ai-chat/FileDiffView.vue) 增加按钮
- 变更面板：[AiChatView.vue](../../src/views/ai-chat/AiChatView.vue) 变更文件区
- 后端：新增 `POST /ai/chat/sessions/:id/changes/:file/accept|reject`
- 工具：[workspace_changes.py](../../server/utils/workspace_changes.py) 增加 revert 方法

### F4. 流式自动滚动控制

#### 2.4.1 背景与痛点

流式响应中，新内容不断追加导致列表自动滚到底部；若用户向上回看历史，会被流式输出反复打断拉回底部。Claude TUI 有「Scroll to bottom」按钮和自动滚动开关。

#### 2.4.2 功能描述

检测用户是否在底部附近，据此决定是否自动滚动；用户离开底部时停止自动滚动并显示「↓ 回到底部」浮动按钮。

#### 2.4.3 详细需求

1. **滚动检测**：监听消息列表 `scroll` 事件，计算 `scrollHeight - scrollTop - clientHeight < threshold`（threshold=80px）判断是否"在底部"。
2. **自动滚动**：流式追加内容时，仅当"在底部"为 true 才调用 `scrollToBottom`。
3. **回到底部按钮**：用户离开底部时，右下角显示浮动按钮「↓」带未读内容条数提示；点击回到底部并隐藏按钮。
4. **新消息提示**：流式期间累计未读消息/字符数，显示在按钮上如「↓ 12 条新内容」。

#### 2.4.4 交互设计

```
┌─ 消息列表（用户在上方回看）──────────────────┐
│  [历史消息...]                                │
│                                              │
└──────────────────────────────────────────────┘
                            ┌──────────────────┐
                            │ ↓ 12 条新内容     │  ← 浮动按钮
                            └──────────────────┘
```

#### 2.4.5 预期效果

- 流式期间用户可自由回看历史不被打断
- 有明确的"回到最新"入口
- 未读内容量可见

#### 2.4.6 验收标准

- [ ] 用户在底部时流式自动滚动
- [ ] 用户向上滚动后停止自动滚动
- [ ] 显示「↓ Nx」浮动按钮
- [ ] 点击按钮回到底部并清除提示
- [ ] 阈值 80px 内仍视为"在底部"

#### 2.4.7 涉及代码

- 前端：[AiChatView.vue](../../src/views/ai-chat/AiChatView.vue) 消息列表 `ElScrollbar` 增加 scroll 监听
- store：[aiChat.ts](../../src/stores/aiChat.ts) 流式追加逻辑配合

### F5. Plan 模式

#### 2.5.1 背景与痛点

当前 Agent 直接执行，复杂任务可能跑偏后浪费大量 token。Claude TUI 有 Plan 模式：先输出执行计划，用户确认后再执行。OpenCode 已内置 `plan` agent，但前端无显式入口。

#### 2.5.2 功能描述

在 composer 增加「Plan 模式」开关；开启后该回合使用 `plan` agent，Agent 只输出计划不执行工具；计划展示后用户点「确认执行」切回普通模式继续。

#### 2.5.3 详细需求

1. **开关**：composer 工具栏增加「Plan 模式」切换按钮（图标：📋），开启时高亮。
2. **发送**：开启 Plan 模式时，`send_message` 的 `agent` 参数传 `plan`（或专门的 `mode: 'plan'` 字段）。
3. **计划展示**：Plan agent 返回的计划以 TodoList 形式展示（复用 [TodoListBlock.vue](../../src/components/ai-chat/TodoListBlock.vue)），每项带 checkbox。
4. **确认执行**：计划下方「确认执行」「修改计划」「取消」按钮。
   - 确认执行：关闭 Plan 模式，将计划作为上下文发送新一轮普通模式消息
   - 修改计划：用户在输入框追加要求，再发一轮 Plan
   - 取消：结束本轮，不执行
5. **会话级**：Plan 模式状态按会话持久化，避免切换会话丢失。

#### 2.5.4 交互设计

```
┌─ composer ────────────────────────────────────┐
│ [📋 Plan 模式 ON]  [模型▾] [Agent▾]          │
│ ┌──────────────────────────────────────────┐  │
│ │ 帮我重构 auth 模块                      │  │
│ └──────────────────────────────────────────┘  │
│                                  [发送]       │
└──────────────────────────────────────────────────┘

→ Agent 返回计划：
┌─ 执行计划 ─────────────────────────────────┐
│ ☐ 1. 分析当前 auth 模块结构               │
│ ☐ 2. 提取 JWT 验证到独立中间件            │
│ ☐ 3. 更新路由集成                         │
│ ☐ 4. 补充单元测试                         │
│ [确认执行] [修改计划] [取消]              │
└──────────────────────────────────────────────┘
```

#### 2.5.5 预期效果

- 复杂任务先规划后执行，减少跑偏
- 用户对执行路径有显式确认权
- 节省 token 浪费

#### 2.5.6 验收标准

- [ ] Plan 模式开关可切换
- [ ] 开启时该回合使用 plan agent
- [ ] 计划以 TodoList 形式展示
- [ ] 确认执行后切回普通模式并发起新回合
- [ ] 修改计划/取消正常工作
- [ ] 状态按会话持久化

#### 2.5.7 涉及代码

- 前端：[AiChatView.vue](../../src/views/ai-chat/AiChatView.vue) composer 增加 Plan 开关
- 后端：[ai_chat.py](../../server/routes/ai_chat.py#L380-L481) `send_message` 接收 `mode` 参数
- 计划展示：复用 [TodoListBlock.vue](../../src/components/ai-chat/TodoListBlock.vue)

### F6. 会话搜索

#### 2.6.1 背景与痛点

会话列表仅按时间排序，无法搜索内容。历史会话多了之后无法定位"上次讨论 X 问题的会话"。Claude TUI 支持历史搜索。

#### 2.6.2 功能描述

在会话列表顶部增加搜索框，支持按**标题 + 消息内容**全文搜索，匹配会话高亮并置顶。

#### 2.6.3 详细需求

1. **搜索框**：会话列表顶部增加输入框，支持 `Ctrl+K` 聚焦。
2. **搜索范围**：会话标题 + 所有消息的 text part 内容。
3. **后端接口**：新增 `GET /ai/chat/sessions/search?q=关键词`，返回匹配会话列表 + 命中片段摘要（前 50 字符 + 高亮）。
4. **实现方式**：
   - MVP：PostgreSQL `ILIKE '%q%'` 全表扫描（会话量 < 1万时足够）
   - 进阶：PG `tsvector` 全文索引或迁移到 Elasticsearch
5. **结果展示**：匹配会话置顶，标题/摘要中关键词高亮；未匹配时显示「无匹配会话」。
6. **清空**：清空搜索框恢复默认列表。

#### 2.6.4 交互设计

```
┌─ 会话列表 ──────────────────────────────┐
│ 🔍 [搜索会话内容...]            Ctrl+K  │
├──────────────────────────────────────────┤
│ ▸ auth 模块重构讨论  (命中: "JWT 验证…")│
│ ▸ 昨天的数据导出问题                    │
│ ▸ ...                                   │
└──────────────────────────────────────────┘
```

#### 2.6.5 预期效果

- 用户可快速定位历史会话
- 关键词高亮帮助判断相关性

#### 2.6.6 验收标准

- [ ] 搜索框可输入并触发搜索
- [ ] 匹配标题和消息内容
- [ ] 结果中关键词高亮
- [ ] 无匹配时显示空状态
- [ ] 清空后恢复完整列表
- [ ] `Ctrl+K` 聚焦搜索框

#### 2.6.7 涉及代码

- 后端：[ai_chat.py](../../server/routes/ai_chat.py) 新增 search 路由
- 前端：[AiChatView.vue](../../src/views/ai-chat/AiChatView.vue) 会话列表区增加搜索框

### F7. 图片粘贴与拖拽上传

#### 2.7.1 背景与痛点

当前仅支持点击按钮选文件上传（[AiChatView.vue#L498](../../src/views/ai-chat/AiChatView.vue#L498)），不支持 Ctrl+V 粘贴图片或拖拽上传。截图交流是高频场景。Claude TUI 支持直接粘贴图片。

#### 2.7.2 功能描述

支持在输入框 `Ctrl+V` 粘贴剪贴板图片、拖拽图片到聊天区上传；上传后作为附件展示并发送给多模态模型。

#### 2.7.3 详细需求

1. **粘贴**：输入框 `paste` 事件检测 `clipboardData.items` 中的 image 类型，提取为 File 对象走现有 `uploadAttachment` 流程。

3. **视觉反馈**：拖拽进入时聊天区显示「拖拽到此处上传」遮罩；粘贴成功后 toast 提示。
4. **多模态**：若当前模型不支持图片，粘贴时提示「当前模型不支持图片，请切换到多模态模型」。
5. **附件展示**：图片附件在输入框上方显示缩略图 chip。

### F8. 工具权限管理

#### 2.8.1 背景与痛点

Agent 可调用所有已注册的 MCP 工具，无 granular 权限控制。某些工具（如删除数据、执行脚本）在特定场景应禁用。Claude TUI 有 `/permissions` 管理。

#### 2.8.2 功能描述

会话级工具权限配置，可选择「允许」「询问」「拒绝」三种策略；Agent 调用受限工具时按策略执行。

#### 2.8.3 详细需求

1. **策略**：每个工具三种策略
   - `allow`：自动执行
   - `ask`：调用时弹窗询问用户（复用 pending question 机制）
   - `deny`：直接拒绝，Agent 收到 "tool not permitted"
2. **配置入口**：composer 工具栏「⚙ 工具权限」按钮打开抽屉，列出所有 MCP 工具，每项下拉选策略。
3. **默认策略**：读类工具默认 `allow`，写/删/执行类默认 `ask`，可在全局配置设默认。
4. **持久化**：会话级配置存 `ai_chat_sessions.tool_permissions`（JSONB），全局默认存 `ai_settings`。
5. **运行时**：OpenCode 调用工具前询问 Flask（或通过 MCP server 中间件拦截），按策略执行/询问/拒绝。

#### 2.8.4 交互设计

```
工具权限抽屉：
┌─ 工具权限 ────────────────────────────────┐
│ MCP Server: platform                      │
│  data_query        [允许 ▾]              │
│  data_update       [询问 ▾]              │
│  data_delete       [拒绝 ▾]              │
│  run_script        [询问 ▾]              │
│ MCP Server: filesystem                   │
│  read_file         [允许 ▾]              │
│  write_file        [询问 ▾]              │
│ [恢复默认]                  [保存]       │
└──────────────────────────────────────────┘
```

#### 2.8.5 预期效果

- 敏感工具调用前需用户确认
- 不同会话可有不同权限策略
- 防止 Agent 执行危险操作

#### 2.8.6 验收标准

- [ ] 工具权限抽屉可打开并配置
- [ ] 三种策略可选
- [ ] `ask` 策略工具调用时弹出询问
- [ ] `deny` 策略工具被拒绝
- [ ] 配置按会话持久化
- [ ] 全局默认可配置

#### 2.8.7 涉及代码

- 后端：[ai_chat.py](../../server/routes/ai_chat.py) 新增权限配置路由
- 拦截：MCP server 中间件或 OpenCode tool 拦截
- 前端：[AiChatView.vue](../../src/views/ai-chat/AiChatView.vue) 新增权限抽屉组件

### F9. 长任务完成通知

#### 2.9.1 背景与痛点

Agent 执行长任务（如批量数据处理、复杂构建）时，用户需切回页面查看是否完成。无后台通知机制。Claude TUI 用终端 bell 提示。

#### 2.9.2 功能描述

当 Agent 回合完成（`session.idle`）且页面不在焦点或会话不在当前激活时，发送浏览器通知 + 声音提示。

#### 2.9.3 详细需求

1. **触发条件**：
   - `session.idle` 事件到达
   - 且（页面 `document.hidden` 为 true 或 当前激活会话 ≠ 事件会话）
   - 且 该回合耗时 > 阈值（默认 30s，可配置）
2. **浏览器通知**：使用 `Notification API`，标题「AI 助手任务完成」，body「会话: {title}」，点击聚焦到对应会话。
3. **声音**：播放短促提示音（可在设置开关）。
4. **Tab 标题**：未聚焦时 tab 标题显示「(完成) AI 助手」或未读数「(3) AI 助手」。
5. **权限**：首次开启通知时请求 `Notification.requestPermission()`。
6. **开关**：设置项「长任务完成通知」可关闭。

#### 2.9.4 交互设计

```
浏览器通知：
┌──────────────────────────────────────────┐
│ 🤖 AI 助手任务完成                       │
│ 会话: auth 模块重构讨论                  │
│ 点击查看                                 │
└──────────────────────────────────────────┘

Tab 标题：(1) AI 助手 - check-manage
```

#### 2.9.5 预期效果

- 用户可切走做其他事，完成时被通知
- 点击通知直接回到会话
- 不打扰关闭通知的用户

#### 2.9.6 验收标准

- [ ] 长回合完成后页面未聚焦时发通知
- [ ] 点击通知聚焦到对应会话
- [ ] Tab 标题显示未读数
- [ ] 声音开关生效
- [ ] 通知开关生效
- [ ] 耗时 < 阈值时不通知

#### 2.9.7 涉及代码

- 前端：[AiChatView.vue](../../src/views/ai-chat/AiChatView.vue) 监听 idle 事件
- store：[aiChat.ts](../../src/stores/aiChat.ts) 事件处理增加通知逻辑

### F10. 消息折叠

#### 2.10.1 背景与痛点

长工具输出（如大段查询结果、长代码块）占据大量屏幕空间，影响后续消息可读性。当前无折叠机制。Claude TUI 自动折叠长输出。

#### 2.10.2 功能描述

对超长内容（工具结果、代码块、文本块）自动折叠，显示前 N 行 + 「展开」按钮；用户可手动展开/折叠。

#### 2.10.3 详细需求

1. **自动折叠阈值**：
   - 工具结果：> 20 行自动折叠
   - 代码块：> 30 行自动折叠
   - 纯文本消息：> 50 行自动折叠
2. **折叠展示**：前 N 行 + 「⋯ 展开（共 X 行）」按钮。
3. **展开**：点击展开全部内容，按钮变为「收起」。
4. **手动控制**：每个可折叠块右上角始终有折叠/展开切换图标。
5. **流式期间**：流式追加时不折叠（保持完整可见），idle 后若超阈值再折叠。
6. **记忆**：用户手动展开/折叠的状态在会话内保持。

#### 2.10.4 交互设计

```
工具结果（折叠态）：
┌─ 🔧 data_query ──────────────────────────┐
│ {"id":1,"name":"test","value":123}       │
│ {"id":2,"name":"demo","value":456}        │
│ ...                                       │
│ ▾ 展开（共 128 行）                       │
└──────────────────────────────────────────┘

代码块（折叠态）：
┌─ typescript ─────────────────────────────┐
│ function auth(req: Request) {             │
│   const token = req.headers.get('auth')   │
│ ...                                       │
│ ▾ 展开（共 85 行）            [复制]      │
└──────────────────────────────────────────┘
```

#### 2.10.5 预期效果

- 长输出不占满屏幕，消息列表更紧凑
- 用户可按需展开查看详情
- 流式期间不被折叠打断

#### 2.10.6 验收标准

- [ ] 工具结果超 20 行自动折叠
- [ ] 代码块超 30 行自动折叠
- [ ] 折叠态显示前 N 行 + 展开按钮
- [ ] 点击展开/收起正常工作
- [ ] 流式期间不折叠
- [ ] 手动状态会话内保持

- 前端：[ToolCallBubble.vue](../../src/components/ai-chat/ToolCallBubble.vue) 增加折叠逻辑

## 3. 实施路线图

### 3.1 建议分期

**第一期（高频痛点，无外部依赖）**：
- F4 流式自动滚动控制（工作量小，体验提升大）
- F10 消息折叠（工作量小，可读性提升大）
- F7 图片粘贴与拖拽上传（工作量小，高频需求）
- F9 长任务完成通知（工作量小，体验提升大）

**第二期（核心功能，中等依赖）**：
- F1 Token 用量与上下文水位线（需 OpenCode 配合暴露 usage）
- F2 @-mention 文件路径（依赖文件树接口）
- F6 会话搜索（依赖搜索接口）

**第三期（安全与控制，重依赖）**：
- F3 Diff 审批/拒绝（依赖 git 回滚 + 审计）
- F5 Plan 模式（依赖 OpenCode plan agent）
- F8 工具权限管理（依赖 MCP 拦截层）

### 3.2 依赖关系图

```
F4 ──┐
F10 ─┤ 无依赖，可并行
F7 ──┤
F9 ──┘

F1 ── OpenCode 事件 usage 字段
F2 ── 工作区文件树接口（已有 list_session_files）
F6 ── PG 全文搜索（无新依赖）

F3 ── F2（可选：文件引用与 diff 关联）
F5 ── OpenCode plan agent（已内置）
F8 ── MCP server 拦截层（需改造）
```

### 3.3 风险与约束

| 风险 | 说明 | 缓解 |
|------|------|------|
| OpenCode 不返回 usage | F1 依赖 token usage 字段 | 后端按字符数估算兜底 |
| 多模态模型不可用 | F7 图片功能依赖多模态 | 不支持时提示切换模型 |
| MCP 拦截改造大 | F8 需改 MCP server 中间件 | 可先用 ask 策略 + Question 机制 |
| Plan agent 行为不确定 | F5 依赖 OpenCode plan agent 能力 | 先验证 plan agent 输出格式 |
| 通知权限被拒 | F9 用户可能拒绝通知权限 | 降级为 tab 标题未读数 |
