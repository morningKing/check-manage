# 域⑨ AI 智能助手

> 架构图对应：业务域 ⑨（AI 智能助手）+ 右侧 AI 子系统（OpenCode / MCP Server）。索引见 [`README.md`](./README.md)。
>
> 本篇是域⑨的**入口页**：只保留域定位、三进程架构一句话、分册导航与跨域依赖。原模块组成、数据模型、核心流程、接口表等细节已全部下沉至 [`ai/`](./ai/00-总览与功能清单.md) 分册库（00 总览 + 01–12 主题册），以分册为权威版本。

## 1. 模块职责

平台与 AI 能力的唯一桥梁。能力以三种形态交付：**对话助手**（流式、工具调用、制品）、**批任务**（N 文件并发无人值守）、**定时 AI 流水线**（扫描数据页→AI 处理→结构化回写）；在此之上提供编排 DAG、动作门禁与审批、执行审计与轨迹分析、Skill 治理与长期记忆等支撑面，并经 `/v1` 开放 API 把 AI 能力暴露给外部系统。核心理念：**浏览器只与 Flask 通信**；平台能力经**独立 MCP Server** 暴露给 Agent，且受同一套 RBAC 约束——「加 skill 即获得能力，前端零修改」。各能力的权威设计见下方分册导航。

## 2. 架构一句话

三进程拓扑：浏览器只与 **Flask**（默认 3002，AI 网关 + SSE 代理，批 worker/看门狗/调度器宿主）通信；**OpenCode serve**（默认 4096）是 Agent 运行时，编排会话与工具调用并调用外部 LLM Provider；**MCP Server**（默认 3003）把平台能力暴露为 27 个 MCP 工具，身份来自会话令牌回查 DB、按 RBAC 过滤工具面。拓扑、会话身份链路与运行时细节见分册 [01-总体架构与运行时](./ai/01-总体架构与运行时.md)。

## 4. 跨域依赖

- **[域① 认证与权限](./01-认证与权限.md)**：全部 AI 入口走会话鉴权（`write_required` 等）；MCP 工具经会话令牌反查 `user_id/role`，施加同一套 RBAC（分册 01）。
- **[域② 配置中心](./02-配置中心.md)**：定时扫描的字段映射与回写校验依赖字段配置。
- **[域③ 动态数据核心](./03-动态数据核心.md)**：定时扫描把数据页记录当待办队列——`FOR UPDATE SKIP LOCKED` 原子认领、JSON 结构化回写同一条记录（分册 07）。
- **[域⑧ 运维监控](./08-运维监控.md)**：系统备份把长期记忆向量库 `MEM0_STORE_ROOT`（`vector_store/`）与数据文件 `DATA_FILES_ROOT`（`data_files/`）整目录打包/还原，使记忆数据与 PG 内引用配套一致（分册 09）。
