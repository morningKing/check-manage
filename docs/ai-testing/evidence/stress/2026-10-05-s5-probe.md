# S5 探针：树作用域场景「事件驱动发现子代理」可行性（2026-10-05）

**结论：可行** —— stub 总线的委派事件形状（tool:'task' part 携 `state.metadata.sessionId`=子 oc sid）能被 `utils/chat_persist.py` 的 `apply_event` **原样发现**为子代理作用域并完整累积子时间线（不改任何生产代码）。S5 场景**无需**走 spec §5 预声明的 DB 种子降级预案（Task 9 不必启用降级分支）。

## 关键证据

- 判别用例：`server/tests/test_runtime_event_bus.py::test_delegate_discovers_subtask`（profile `{'delay_ms': [10,20], 'delegate': ['explorer'], 'tool_parts': 1}`）。实现前红灯 `AssertionError: 委派未被发现: subtasks=[]`；实现后**连跑 5 次全绿**（0.30–0.37s，无偶发）。
- 发现路径（逐帧核对 `apply_event`）：父轮 `message.updated` 先注册 assistant msg id → tool:'task' part 事件到达（`props.sessionID`=父 sid 命中顶层 scope）→ 从 `part.state.metadata.sessionId` 提取子 oc sid → `_discover_subtask` 注册 `state['subtasks'][child_sid]`（agent='explorer'，description/prompt 从 tool input 带出）→ 随后子会话的 `message.updated`/parts/idle 按 `props.sessionID` 路由键命中子 scope。
- 断言落点：`state['subtasks']` 恰 1 项；`scope['status'] == 'completed'`（子 `session.idle` 到达即翻转）；`child_oc.startswith('stub_')`；子会话 REST 视图独立存在（`get_messages(child_oc)[-1]['info']['finish'] == 'stop'`）——「账本按 oc_session_id 归账」的锚成立。
- 实现侧前提（`server/utils/runtime/stub.py`，Task 2 落地）：委派段在父轮 tool parts **之前** emit（先发现、后收子事件，顺序不可倒置）；子会话时间线由 `_append_terminal(child_sid, child_s, 'stop', delegate=False)` 内联跑完（不级联委派，树深恒 1 层）；`_lock` 为 RLock（持锁递归 `create_session` 不死锁）。
- 局限：探针覆盖**单层委派、同步内联收敛**（无并发交错的子代理）；真实 OpenCode 的多子代理并发交错事件流不在本探针范围，S5 压测场景本身仍由 Task 9 以真实事件流复核。
