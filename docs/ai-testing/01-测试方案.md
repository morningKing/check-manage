> 配套文档：[02-AI功能测试用例.md](./02-AI功能测试用例.md) ｜ [03-测试执行报告.md](./03-测试执行报告.md) ｜ [04-缺陷记录与修复.md](./04-缺陷记录与修复.md)

## 1. 背景与目标

check-manage 平台围绕 OpenCode Agent 运行时 + 独立 MCP Server 构建了九大 AI 能力族。本测试旨在**全量验证 AI 能力的功能完整性、健壮性、可靠性与安全性**，并沉淀可复用的全量回归测试资产（Playwright 脚本 + 测试中间件），供后续全量 AI 测试直接复用。

### 2.2 明确排除

- 非 AI 的数据管理功能（动态数据 CRUD、项目版本、依赖、Webhook 引擎本身、ETL、导出脚本引擎本体等）——仅在与 AI 交互相交时顺带覆盖（如行操作 AI 按钮、MCP 数据工具）。
- 智能客服 kefu（独立能力族，本次不展开，仅验证与 MCP 白名单相关的边界）。

## 5. 测试策略（三层）

### L1 单元/组件层（pytest + vitest）
- 存量 2007 后端 + 1114 前端用例保持全绿。
- **查漏补缺**（AI 部分）：补齐 `sweep_orphans`、`runtime_state`、`ai_session_repo`、`skillopt`、`routes/ai_skills`、`_reconcile_stale_running` 404/不可达分支、对外 DELETE 终态门、settings 掩码边界、internal search limit 非数字等缺口。
- **效率优化**（不改测试功能）：后端引入 pytest-xdist 并行 + 收敛 autouse fixture 开销；前端收敛重复 polyfill/stub 到公共 setup + 并行参数调优。优化前后各测一次时长留证。

### L2 API 层（pytest 接口测试 + Playwright APIRequestContext）
- 对外 OpenAPI 全家族：鉴权（未绑定密钥 403、无效 key 401）、隔离（api_key_id/user_id/staging 归属）、边界值（50 文件、101MB/1MB 体积门、411 chunked）、状态机（终态门 409、append 拉回 running、回调重复收敛）、安全（路径归属校验、穿越拒绝、HMAC 签名验证、output 只在 completed 返回）。
- 内部端点健壮性：畸形/缺字段/非数字 limit/超长输入/并发。
- MCP：token 过期/吊销 401、RBAC（guest 只读、kefu 白名单）、工具越权拒绝。

### L3 E2E（Playwright 真实链路，归档于 `e2e/ai-full/`）
- 真实 AI 会话收发（真实 OpenCode 回复，非 mock）。
- 真实批任务：创建→运行→子会话查看→重试/重执/编辑配置→删除。
- 定时任务：run-now 真实跑一行数据→回写状态字段。
- MCP 能力：会话内让 Agent 真实调用 MCP 工具（查数据/存产物/记忆工具），断言工具气泡与产物。
- 治理审计：关闭/重开/清空/归档 + operation_logs 落痕 + 管理页审计视图。
- 长任务：真实长回合验证停止/续跑/进度持久化（预算充足，明确允许长任务）。
- 留证：截图存 `e2e/screenshots/ai-full/`，关键证据归档 `docs/ai-testing/evidence/`。

### 8.2 关键不变量（回归必须守住）

1. 任一子会话同时最多一个 active turn（DB 部分唯一索引）；
2. 终态写入全部经 `batch_repo.transition_child` CAS；批次计数 = rowcount=1 驱动；
3. 旧 generation / 旧 fencing token 的写回不改变任何状态、计数与消息；
4. 非终态批任务在内外两个入口都无法直接删除（`BATCH_NOT_TERMINAL` / `BATCH_DRAIN_TIMEOUT`）；
5. 生效 actionChecks 登记不可证实时子任务不得 `completed`（`gate_status='inconclusive'`）；
6. 多进程部署只有一个 batch/delivery/scheduler 实例（三把独立租约）；
7. 同一 `Idempotency-Key` 的命令不重复执行；事件 seq 并发严格单调；
8. unknown effect 一律进 `needs_review`，禁止自动重放。

### 8.3 已知与既有行为的契约变化（测试同步更新处）

- `_mark_*` CAS 要求 `status='running'`：直接驱动 worker 的单测需把种子行置 running 并带 `execution_generation`（`test_batch_engine` / `test_batch_auto_retry` / `test_batch_standalone_prompt_retry` / `test_ai_scan_engine` 已适配）；
- `validate_checks` 规范化输出新增 `apply_to` 键（未声明为 None）；
- Open API `DELETE` 非终态 409、`actionChecks` 非法 400（`ACTION_CHECK_INVALID`）；
- 批子会话普通发送：非终态 409 `BATCH_SESSION_CONTROLLED`（终态放行，前端走 continue 端点）。
