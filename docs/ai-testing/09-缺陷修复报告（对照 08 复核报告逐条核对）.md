**E2E 稳健性加固（本轮实测发现）**：`ai-harness-safety` 全链路用例的 UI 观察段存在固有竞态——真实模型对小文件的批任务约 6 秒跑完，用例经 API 观察到子会话 `running` 再导航 UI 时，批已可能落终态；且 `?session=<子会话>` 深链挂载链存在瞬态竞态（批量列表/详情 fetch 偶发落空，见 §9 观察）。处置：门禁行为以 **API 409 断言为确定性核心**（`BATCH_SESSION_CONTROLLED`，等价 pytest 覆盖），UI 段改为「导航重试等状态条出现（3 次）+ 出现后断言合法状态文案（运行/终态均可）+ 仍无则降级告警」——与该用例既有的「跑得太快」降级模式一致。修复后单文件 3 passed（含 P2 三节点 DAG 真实审批链路）。

**断言强度原则**（回应 08 §6.2「断言过弱」）：新增测试一律断言**副作用落库结果**（计数器、行数、状态机、唯一索引行为），不断言「调用了」；插件契约测试对齐 callID 流程后断言端点与字段存在性。

**测试污染**（08 §6.2）：p2 裸 DELETE 已收口（§2 M8）；新测试文件自带按用户/批次隔离的 teardown（含 `ai_batch_events` 无 FK 表的显式回收与 `db_conn.rollback()` 防错误态传染），两轮连跑验证幂等。

**07 号「e2e 28 passed 不可能覆盖最终版本」的验证完整性问题**（08 §6.3）：本报告的 e2e 在「提交 25d0eef 内容 → 重启 → 跑」的顺序下执行，进程启动时间与提交内容的先后关系见 §5/§8。
