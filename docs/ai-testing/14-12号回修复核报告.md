13 号声称"e2e 窗口内 2 条 `ai_batch_completed` 回调记为 failed 且 attempt_count=4——修复前会被假记 delivered；dead_letter/退避在 HTTP 失败面真实可用"。

**证据失实之处**：

2. "attempt_count=4" 是当时查询的快照值（测试中退避 4 次时触发）；复核时已到 8（dead_letter）。

**机制层面仍成立**：failed/dead_letter 行确实存在（非 12 号时的全 delivered），webhook_logs 里对应行 `response_status=NULL, success=false` 证明超时/连接失败被正确分类并重试至 dead_letter。因此 outbox 分类修复的**机制有效性**有数据支撑，但"e2e 证据"的引用不成立。

## 7. 残留与建议

### 7.1 代码层面

本轮 8 项核心问题在代码层面**已全部落地**（12 号遗留的 deliver_one 无效分支、anchor 未传、迁移 DDL、PG 校验、docstring 均已修复）。残留均为低风险：

| 项 | 说明 |
|---|---|
| `settle_effect` 不允许 `failed→unknown` | 偏保守（unknown 触发人工复核），无自动重放风险；后续批次 |
| `settle_effect_by_key` 未按 session 限定 | eid 随机 14 hex，跨 session 碰撞概率极低 |
| M3 其他变更入口无门禁（abort/close/clear 等） | 预存在，非本轮引入 |
| MCP/文件/扫描 effect 无生产写入 | 12/13 号已确认属后续批次 |
| M8 批次臂仍按名称过滤 | 13 号已收紧为显式清单（含 `AITEST-%` + 固定名）；真实批次不会命中保留前缀 |

### 7.2 报告层面

- **13 号 §5 e2e 证据不成立**：被引用的 failed 行是测试夹具残留，不是 e2e 回调；outbox 失败分类的机制有效性可通过 webhook_logs 与 dead_letter 行佐证，但不应引用为 e2e 证据。
- **判别力表中 M3/subtask compact 与 heartbeat 两例声称 base 失败，实为 PASSED**（回归锁，非判别器）。

### 7.3 泄漏与测试隔离

13 号声称"每轮 +99→0-1"，精确含义是：conftest 会话末 GC 清空孤儿；底层泄漏率基本未变。**建议后续将 `tests/conftest.py` 的全表 anti-join DELETE 改为会话局部回收**（例如只删 `created_at > session_start` 的行，或用临时表标记）；同时扩展其他 12 个泄漏测试文件的 fixture 回收（仅 H4/p2/audit 已修，其余不变）。
