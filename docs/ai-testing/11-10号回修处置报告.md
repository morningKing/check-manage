## 1. 必修项（§8-1/2/3）逐条处置

### 1.1 H4① CAS 谓词收窄（10 号 §4：实际未修且声明不符）

**处置：真收窄**。`orchestration_engine._launch_agent_step` 的派发 CAS 改为 `AND status='blocked'`（原 `IN ('blocked','failed')`），注释同步更正——failed 且有 attempt/session 的重试本就走上方复用分支（CAS `'running'`），其余 failed 形态（blocked 快照后并发转 failed）不再复位 attempt_count、不再弃用原会话新建（10 号补充判定确认收窄安全）。

**判别性测试** `test_h4_failed_step_not_redispatched`：DB 中把 step 置 `failed`（attempt_count=0、无会话）后调 `_launch_agent_step` → 断言不新建会话、attempt_count 仍 0。**base（d5a0347 后任何版本）上该测试必失败**（旧谓词会命中 failed 并建会话）——判别力实证。

| 子项 | 处置 | 证据 |
|---|---|---|
| ① 非同事务 | `record_effect` 增加 `conn` 参数：传入时在调用方事务内 SAVEPOINT（`eff_rec`）登记，随外层一起提交/回滚，不留孤儿 planned；`batch_repo.recompute_batch_status_tx` 与 `batch_engine._recompute_batch_status` 两处调用点均改传 `conn=conn` | `test_record_effect_same_transaction_rollback`：外层 rollback 后 effect 行=0（base 上 `record_effect` 无 conn 参数，测试 ImportError/TypeError 必失败） |

### 1.3 M6（10 号 §3.3：恒真式 / 与 base 逐字同 / 6 处不传 token / 测试固化无防护）

**处置：fencing_token 必填 + 全部调用点传真值 + 删除恒真兜底**。
