# 单元测试执行效率优化报告

> 约束：**不改变任何测试的功能与断言**，只优化执行方式。所有优化前后均做全量对照。
> 环境：Windows 10 x64 / 8 核 / Python 3.12 / Vitest 4。

## 1. 前端（Vitest）

### 基线（优化前）
- 命令：`npm run test`（vitest run）
- 结果：**116 文件 / 1164 用例 / 110.02s**
- 耗时构成（vitest 统计）：environment 448.66s（累计）、import 202.93s、transform 18.21s、**tests 本体仅 19.43s**——开销几乎全在每文件 jsdom 环境创建与模块导入，而非测试本身。

### 优化动作
1. **纯逻辑测试切换 node 环境**：为 `src/utils/__tests__/` 下 21 个不依赖 DOM 的测试文件添加
   `// @vitest-environment node` 文件级标注（排除需要 `document` 的 clipboard.test.ts 与
   走 axios/window 的 request.test.ts）。这类文件不再创建 jsdom 实例。
2. **公共 ResizeObserver polyfill**：`src/test/setup.ts` 统一注入 `ResizeObserver`
   （约 20 个组件测试文件原本各自复制粘贴），新测试可直用；存量副本无害、逐步清理。

### 结果（优化后）
- **120 文件 / 1196 用例（含本轮新增 32 例）/ 107.43s**；environment 累计 448.66s → **382.97s**。
- 墙钟降幅有限的原因：vitest 4 默认 forks 池已按 8 核并行，墙钟受"最慢单文件"与调度影响；
  主要收益体现在吞吐（environment 累计耗时 -15%）与新增文件零成本扩展。
- 结论：**测试功能与断言零变化，全量 1196 例绿**。

## 2. 后端（pytest）

### 基线（优化前）
- 命令：`npm run test:server`（单进程串行）
- 结果：**2062 passed / 4 failed（存量缺陷，已在 04 号文档修复）/ 1 skipped / 369.74s**

### 慢点剖析（--durations=25）
| 慢点 | 单例耗时 | 原因 |
|------|----------|------|
| `test_script_runner.py`（53 例） | ~5s/例 ≈ **100s** | 沙箱脚本在 Windows spawn 子进程执行，**每次**都要冷启动解释器并重新 import pandas/numpy |
| `test_ai_opencode_admin.py::test_restart_guard_and_force` | 10.0s | 真实进程管理（属功能语义，不动） |
| `test_menu_export.py` / `test_routes_menu_export.py` | ~14s 合计 | 同 script_runner（走同一沙箱） |
| `test_ai_scan_engine.py` 个别真实链路用例 | 8.7s | 真实 AI 执行（属功能语义，不动） |

### 优化动作
1. **script_runner 常驻 worker 进程**（`server/utils/script_runner.py`）：
   - 旧实现：每个脚本一个一次性 `multiprocessing.Process`（Windows spawn → 每脚本 ~5s 冷启动）；
   - 新实现：一个**常驻** worker 顺序执行脚本，每个脚本仍是全新命名空间
     （`_build_safe_globals` + script_locals 每次重建；沙箱禁 import/setattr，脚本无法污染
     共享模块对象）；**超时/worker 死亡即杀掉并重建**，保持"失控脚本不毒化下一次执行"的旧语义；
     环境 IPC 不可用时照旧落线程兜底。
   - 附带修复：超时路径缺 `import logging`（旧一次性进程版不存在该代码路径；新代码验证时发现并修复）。
   - 验证：`server/test_scripts/verify_script_worker.py` 复用/超时/重建全链路断言通过。
2. **pytest-xdist 并行档**（保守启用）：`requirements.txt` 增加 `pytest-xdist`，
   `package.json` 新增 `test:server:fast`（`-p xdist -n 4 --dist loadfile`）。
   ⚠️ 默认 `test:server` 保持串行：本套件含与 dev 后端共享真实 DB 的集成用例
   （`_reconcile_stale_running` 会重排"非本进程"的 running 行，多进程并行会互相误重排；
   实测 4 workers 期间发生 DB 锁等待导致并行收益为负），详见 README「已知并行限制」。

### 结果（优化后）
- `test_script_runner.py` 53 例：**~100s → 2.19s**（-98%）；menu_export/ETL 等所有走沙箱的测试同步受益。
- 全量串行复测（独占环境最终记录）：**369.74s → 117.49s（-68%，3.1 倍）**，
  2132 passed / 0 failed / 3 skipped（含本轮新增用例），详见 03 号执行报告。
- `test:server:fast` 可用于无 dev 后端环境下的快速迭代（一次性全量并行）。

## 3. 结论

| 套件 | 基线 | 优化后 | 备注 |
|------|------|--------|------|
| 后端 pytest | 369.74s / 2062 例 | **117.49s / 2132 例（-68%）** | script_runner 常驻化（沙箱测试 53 例 ~100s→2.2s）+ 全沙箱链路受益；另提供 xdist fast 档 |
| 前端 vitest | 110.02s / 1164 例 | **88.43s / 1196 例（-20%）** | 21 个纯逻辑套件转 node 环境（environment 累计 -28%）；零断言变更 |

> 前端最终复测：Duration 88.43s，environment 累计 448.66s → 324.04s。测试功能与断言零变化。
