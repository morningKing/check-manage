## 1. 严重缺陷处置（H1–H8，8/8 修复）

### H1 租约心跳线程启动即崩 ✅
- 根因：`_lease_loop` 内 `from utils import execution_lease` 后置，Python 将该名
  视为局部变量，首行 `wait(execution_lease.DEFAULT_HEARTBEAT_SEC)` 即 UnboundLocalError。
- 修复：import 提至函数首行；新增 `test_worker_start_lease_loop_survives`
  （断言 start() 后心跳线程存活）。

### H2 内部 DELETE 缺 drain 超时保护 ✅
- 修复：`routes/ai_chat_batches.py::remove` drain 超时返回
  `409 BATCH_DRAIN_TIMEOUT`（retryable），任务与工作区保留，与对外 API 语义对齐。

### H3 入口 D 补挂期望 fail-open ✅
- 根因：终态判定只看批级 `subagent_reuse`… 更正：只看批级 action_checks 的
  applicable 计数，入口 D 补挂的 per-session 期望被静默忽略。
- 修复：判定信号改为「会话实际评估的期望数」（`gate.results` 长度，含入口 D
  补挂行）与批级 applicable 取并集语义；任一 failed 均阻断（恢复 main 语义）。

### H4 step 转移无 CAS → 并发双派发 ✅
- 修复：`_launch_agent_step` 的 runnable→running 转移改 `UPDATE … WHERE
  status IN ('blocked','failed') RETURNING` CAS——并发推进只有赢家创建子会话。
- 方案取舍：曾实现 run 级 advisory lock，实测孤儿客户端（测试进程被强杀）
  会以 idle-in-transaction 持锁毒化后续所有推进，故回退纯 CAS 方案（无死锁面、
  无全局毒化）。

### H5 steps.output 无生产写入 ✅
- 修复：agent step 成功收口时提取子会话最终 assistant 文本写入
  `steps.output = {"text": …}`（截断 4000 字），条件边判定与
  `{{steps.x}}` 提示词渲染恢复数据来源。

### H6 skipped 不传播 → run 卡 running ✅
- 修复：依赖死态集合纳入 `skipped`——依赖被跳过/失败时下游级联 skip，
  run 状态正确派生（partial/failed），不再永久 blocked。

### H7 effect 账本零写入 ✅（回调链路；MCP/扫描回写为后续）
- 修复：批次终态回调接线 `ai_execution_effects`——`enqueue` 与终态同事务
  写入 effect（幂等键 = event_id + target_url），投递器成功 settle
  `committed`、8 次退避后 `dead_letter` 记 `failed`。
- 后续：MCP 写入/文件导入/扫描回写需 OC runtime 层埋点，随 runtime adapter
  接线批次落地（§11.3 已登记）。

### H8 重启无条件重放 ✅
- 修复：移除 `start()` 两处 `_restart_audit()` 调用（方法保留为兼容空操作），
  遗留 running 行由 `_reconcile_stale_running` 恢复决策表接管（lease 未过期
  等待 / oc 404 失败 / unknown effect → needs_review / 会话存活 → 原地续跑）。
- 测试改写：`test_restart_audit_resets_orphaned_running` 改为决策表路径断言
  （404 → 带准确原因 failed）。
