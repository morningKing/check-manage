## 3. 部分修复（9 项）

### 3.1 H3 —— 异常分支仍 fail-open（**已端到端复现，可达**）

已修部分成立：`agent_ledger.py:534-547` 的 inconclusive 分支携带 `expected`（per-session 计数），引擎判定并入 `expected > 0`（`batch_engine.py:1263-1272`）；实测 `ledger_healthy=False` + 仅入口 D 期望 → fail-closed ✓。

**残留**：同函数兜底分支 `agent_ledger.py:627-629` 返回 `{'status':'inconclusive','results':[],'error':…}`，**不带 `expected`**。此时 `evaluated=0`、`applicable=0`、`expected=0` → `gate_status='skipped'` → `_mark_done`。

可达性（agent 端到端探针，真库 + 真 `_run_one`）：

```
入口 D 形态（批无 action_checks）+ PG 非法正则期望
  → 子任务 completed / gate_status='skipped' / error_message=None（期望从未核对）
同数据放批级 checks（applicable>0）→ 正确落 failed/inconclusive（对照组）
```

触发路径合法：`validate_checks` 用 Python `re` 校验（`agent_ledger.py:255-258`），核对执行用 PG `~`；`(?P<x>a)` 被 Python 接受、被 PG 拒绝（`invalid embedded expression`），可经 `/action-checks/attach` 写入。

### 3.2 H7 —— 接线存在，但非同事务、settle 语义错、unknown 链路仍是死代码

08 号"全仓零写入方"的判断已不再成立（生产侧 3 处调用点：`batch_repo.py:80`、`batch_engine.py:400`、`delivery_outbox.py:144`），但：

1. **不是同事务**（09 号"同事务登记"不实）：`record_effect` 无 `conn` 参数，自开连接并提交（`execution_effect.py:32-33,49`）；两个调用点都在外层终态事务**提交之前**先提交 effect（外层 commit 分别在 `batch_repo.py:178`、`batch_engine.py:403`）。后果：外层回滚 → 留下**孤儿 planned effect**（outbox 行已回滚，永不 settle）；record 失败 → 回调照常投递但账本无行。
2. **settle 终态语义错**：`settle_effect` 只允许 `planned/started → 终态`（`execution_effect.py:75`）；`delivery_outbox.py:144-147` 把首次失败即写死 `failed` → 后续退避重试成功时 settle 为 0 行 → outbox `delivered` 而 effect 永远 `failed`；`replay_dead_letter` 重放成功后同样无法转 `committed`。
3. **unknown → needs_review 仍是死代码**（09 号"保护链路激活"不实）：全仓生产代码无 'unknown' 写方（仅 `test_harness_p1_durable.py:378`）；投递的不确定结局（HTTP 超时/中断）被一律归为 `failed`（`delivery_outbox.py:177-179`）→ `batch_engine.py:2614-2618` 永不触发。
4. **锚定不可靠**：`batch_engine.py:394-397` 用 `ORDER BY created_at DESC LIMIT 1` 且无 tiebreaker，而同批子会话在同一事务插入、`created_at` 完全相同（dev 库 878 行 session 仅 803 个不同 `created_at`，**62 个批次的"最近子会话"不唯一**）。对比 `batch_repo.py:158-159` 用刚转移的 `sid` 锚定是确定且正确的。
5. **覆盖范围**：`mcp_write`/`file_import`/`scan_writeback`/`artifact` 仍无生产写入方（09 号已承认属后续）；`cancel_child` 的 `recompute_batch_status_tx(cur, batch_id)` 不传 conn（`batch_repo.py:600`）→ 终态不写事件不入队。
6. **零测试**：`settle_effect_by_key` 全仓无测试；09 号"harness P1 套件扩展"不实（`test_harness_p1_durable.py` 本批未改动，最后一次改动在 38deff9，其 `:369-379` 只测原语）。
