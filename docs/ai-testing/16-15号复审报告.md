## 2. 问题明细

### 问题 1（较重要）：README 悬挂未入库的 14 号报告

`git status` 显示 `docs/ai-testing/14-11号复审报告.md`、`docs/ai-testing/14-12号回修复核报告.md` 仍为**未跟踪（`??`）**，而 README 行 19-20（`1171173` 已提交）已链接它们。索引指向仓库中不存在的文件，15 号"14 号索引"实际不闭合。
**建议**：将 14-11/14-12 一并入库（或先移除 README 中的对应行）。

### 问题 2：时间窗 GC 后 dev-server 孤儿不再回收（新增残留，未登记）

14-12 §2.3 已实测：孤儿来源之一是「dev server 对已删批次的 outbox 重投递产生的 `delivery.failed`」——**该来源不在任何 pytest 会话内**，故不会被"本会话时间窗 GC"回收，改前有全局 GC 兜底、改后将永久累积。15 号 §2.3 仅登记"其余 12 个测试文件由本会话 GC 兜底"，未覆盖此非测试来源。
**建议**：为 dev-server 侧加独立的孤儿回收（如 outbox 指向已删批次时不再 append 事件，或定期清理钩子），并在 15 号 §2.3 补记。

### 问题 3：14-12 文件名与内容不符

`14-12号回修复核报告.md` 正文标题为「12 号回修复核报告（14 号）」但复核对象是 `13-12号回修处置报告.md`，按 `N-<被审号>` 约定应为 `14-13号…`。15 号正文已正确描述"13 号处置的运行时复审"，但沿用错误文件名，易致后续引用混乱。

### 问题 4：引用不精确

- §4 称「pytest 全量 2282 passed / 3 skipped（conftest GC 时间窗变更后全绿）」——14-12 同环境实测为 **2281 passed / 1 flaky / 3 skipped**；"2282"本轮无独立复现。
- §结论/前言「两份 14 号报告一致确认 **8 项**核心修复全部落地」——14-11 复核的是 `cb8827e` 的 **7** 项、14-12 复核的是 `83309ed` 的 **8** 项，数字为合并表述。
- 13 号 §1 返回 dict 引用 `:383-392`，实际 `:383-390`（末两行为空行/函数间隔），属微差。
