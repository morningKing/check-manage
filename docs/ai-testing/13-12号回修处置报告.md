## 1. 必修项：`deliver_one` 读返回值（12 号 §3）

**自检确认**：`_fire_single_webhook` 内部自捕获 `Timeout`/`RequestException` 并返回结果 dict（`webhook_engine.py:383-392`），`deliver_one` 的 `try/except` 永不命中、无条件 `return True`——outbox 把 4xx/5xx/超时全部记为 `delivered`，永不退避、永不 dead_letter；本轮新增的 `'uncertain'` 分支生产不可达。**该缺陷自 base（9b280d5 之前）即存在，12 号定性准确。**

**处置**（`delivery_outbox.deliver_one` 重写）：

```python
res = _fire_single_webhook(...) or {}
if res.get('success'):                     return True        # 2xx
if res.get('responseStatus') is not None:  return False       # 4xx/5xx → 退避/dead_letter
return 'uncertain'                                            # 无响应（超时/连接拒绝）→ effect unknown
```

**连带处置（12 号 §4.3 粘滞评估）**：`settle_effect` 允许 **unknown → failed**（后续拿到确定性否定，如 dead_letter 前的 4xx）——与 failed→committed 对称，committed 保持粘性。首次超时不再永久阻断自动恢复。

**测试（真实 `deliver_one` + 网络层打桩，回应 12 号 §6-2）**：`test_deliver_one_real_classification` monkeypatch `webhook_engine.requests.post`（不碰网络），走真实 `_fire_single_webhook` + `deliver_one` + `drain_due_once` 三分支断言：
- 2xx → outbox `delivered` + effect `committed`；
- 500 → outbox `failed`（进退避）+ effect `failed`（**修复前记 delivered+committed，base 上必失败**）；
- Timeout → outbox `failed` + effect `unknown`（**修复前同样 delivered+committed，必失败**）。

`test_settle_unknown_can_fail_later`：unknown→failed→committed 链 + committed 粘性。
