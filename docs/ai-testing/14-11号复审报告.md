## 2. 核心失实 ①：H7③「unknown 写入方」生产不可达（`cb8827e`）

### 2.1 代码事实

被审提交 `cb8827e` 的 `delivery_outbox.py`：

```python
# :171
def deliver_one(row: dict) -> bool | str:
    ...
    try:
        _fire_single_webhook(          # :181  ← 返回值被丢弃
            rule_id=..., timeout=30, retries=0,
        )
        return True                    # :189  ← 无条件成功
    except (_requests.exceptions.Timeout,
            _requests.exceptions.ConnectionError) as e:   # :190  ← 不可达
        return 'uncertain'             # :193
```

而 `_fire_single_webhook`（`webhook_engine.py:311`）**内部已吞掉全部网络异常**（`:365` `except Timeout`、`:368` `except RequestException`），遍历 `retries+1` 次后**返回 dict，从不外抛**。故 `deliver_one` 的 `except (Timeout, ConnectionError)` **永不执行**，`return True` 恒成立。

### 2.2 后果（与 11 号声明相反）

1. `unknown` 永不落库 → `has_unknown_effects → needs_review` 保护链路**仍是死代码**；
2. outbox 可靠投递在 HTTP 失败面实质失效：4xx/5xx、超时、连接拒绝全被记为成功，**永不退避、永不 dead_letter**。

### 2.3 测试为何全绿：绕过了真实实现

`test_review_gap_tests.py:405` 的 `test_outbox_uncertain_delivery_sets_unknown_effect` 在 `:426` 直接 `monkeypatch.setattr(delivery_outbox, 'deliver_one', lambda row: 'uncertain')`，把被测函数整体替换，**从不经过真实 `deliver_one`**。该用例通过不构成生产证据，也不构成 base 判别力（11 号 §4 却把它列为"base 必失败"）。

> 11 号 §1.2③、§3-#3 的两处声明在此证伪。
